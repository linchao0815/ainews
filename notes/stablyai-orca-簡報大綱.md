# Stably Orca 簡報大綱

來源筆記：[stablyai-orca-研究筆記.md](stablyai-orca-研究筆記.md)
重新查證：2026-10-01（gh CLI 查 PR／issue／release 狀態、README、onorca.dev 文件）

**名詞先講清楚（講者備註，第一次出現時口頭帶過）**
- **AI 寫程式助手**：Claude Code、Codex 這類在終端機裡幫你寫程式的工具，以下簡稱「助手」
- **session**：和助手的一段對話，關掉就結束
- **worktree**：同一個專案複製出來的獨立工作資料夾，幾個助手同時改也不會互相踩到
- **PR／issue**：GitHub 上的「待合併的程式修改」／「需求或問題回報」；兩者都**不代表功能已經上線**

---

## 投影片 1｜標題
- Stably Orca：同時指揮多個 AI 寫程式助手的工具
- 副標：能用我們現有的 Claude／Codex 訂閱嗎？額度用完怎麼辦？能取代記憶系統嗎？

## 投影片 2｜結論先講
- Orca 本身**不提供 AI**，它是一個「指揮台」，用的是你自己已經付費的 Claude／Codex 帳號
- **額度用完不會自動接手**：自動等額度恢復、自動換帳號，到最新版 v1.4.218 都還沒有。
  能做的是**事先登記多個帳號，用完時手動切換**
- **它不會幫你記住過去學到的東西**，所以不能取代我們現有的記憶作法（llm-wiki＋auto-memory），兩者是搭配使用

## 投影片 3｜Orca 是什麼
- 官方一句話：「用你自己的訂閱，跑任何 AI 寫程式助手」
- 支援 34 種助手（Claude Code、Codex、Cursor、Copilot、OpenCode、Grok…），只要能在終端機跑的都能接
- 每個助手在**自己的工作資料夾**裡做事，可以讓好幾個同時做同一題，最後挑做得最好的那份
- 電腦（Mac／Windows／Linux）、手機（iOS、Android）都能用，也能連到遠端主機上跑
- 免費開源（MIT 授權），GitHub 約 8.3 萬人按星
- 其他功能：直接看 GitHub／Linear 的工單、點畫面元件讓 AI 改版面（Design Mode）、讓 AI 操作桌面程式（Computer Use）

## 投影片 4｜用自己的訂閱帳號
- Orca 不需要另外買 API，它直接叫起你電腦上已經登入的 Claude／Codex
- **帳號切換**：可以登記好幾組帳號，切換時不用重新登入
- **用量看板**：看得到 5 小時、每天、每週還剩多少額度，以及什麼時候重置
- 每個帳號的設定分開放，不會互相干擾
- 參考價格（月費）：ChatGPT Plus $20、Pro $100 或 $200

## 投影片 5｜Orca 和 Codex 本身差在哪
| | Orca | Codex |
|---|---|---|
| 是什麼 | 指揮台，管很多助手 | OpenAI 自家的一個助手 |
| 能用哪些助手 | 34 種以上，可以同時跑 | 只有 Codex |
| 同時做事會不會打架 | 每個助手一個獨立資料夾 | 只有一個工作區 |
| 帳號 | 可以放多組、不同廠商 | 一個 ChatGPT 帳號 |
| 在哪裡用 | 電腦、手機、遠端主機 | 終端機、桌面版、編輯器外掛、網頁 |

## 投影片 6｜額度用完時，現在怎麼辦
- **沒有自動機制。** 實際作法：打開帳號切換 → 換一個還有額度的帳號 → **開一段新對話**，
  再用「Continue in New Session」把前面聊過的內容帶過去（見投影片 8）
- **為什麼不能直接無縫換？** 換帳號只對「新開的對話」有效，正在跑的那段換不過去（官方已知問題 #19900，還沒解決）
- 「Continue in New Session」目前只有電腦版有，手機版還在排隊（#19374）

## 投影片 7｜分工調度（Orchestration）：一個主管帶一群工人
**白話：** 像專案經理派工。一個助手當主管，把大工作拆成一張張工單，發給其他助手去做；
工人做完要回報「我做的是哪張工單、第幾次派的」，主管對得上才算結案，再決定這個工人收工還是接下一張。

| 官方用語 | 白話 |
|---|---|
| Run | 這次專案的專屬資料夾＋主管信箱（只負責記錄，不會自己派人） |
| Task | 工單：要做什麼、要等哪張先做完、現在做到哪 |
| Dispatch | 這張工單「這一次」交給誰做 |
| Message | 工人和主管之間的信：回報進度、發問、報平安 |
| Decision Gate | 主管還沒拍板的問題；沒拍板，相關工單就先停著 |

- 流程：開專案 → 開工單 → 派工人 → 主管收信 → 工人回報完成
- 為什麼回報要同時對「工單」和「第幾次派」？同一張工單重派過時，才不會把上一次的舊回報誤當成完成
- 做完可以讓工人收工（保存成果、關掉視窗），或先留著方便查問題
- 最新進展：v1.4.218 起，實驗中的聊天介面也能當主管

## 投影片 8｜分工調度和「接手對話」差在哪
**「接手對話」（Continue in New Session）是什麼：** 在助手視窗的選單點這個按鈕，
Orca 會**另開一段新對話**（可以換成別的助手，例如 Claude 換成 Codex），
自動把前面聊過的重點整理好貼給新助手；**原本那段對話不會被關掉**。
要帶多少內容可以選：
- **精簡**（預設）：只帶最新進度和目前的檔案，需要時新助手才回頭翻舊對話
- **完整**：叫新助手把整段舊對話讀完，比較慢，也比較吃額度

| | 接手對話 | 分工調度 |
|---|---|---|
| 一句話 | 一件事**換人接著做** | 一個主管**同時**帶好幾個人分工 |
| 交接什麼 | 前面聊過的內容 | 工單內容、進度、回報 |
| 誰按下去 | 你自己點選單 | 主管助手自己下指令 |
| 幾個助手 | 一個換一個 | 一個帶多個，同時做 |
| 怎麼算做完 | 沒有判定，貼完就交給新對話 | 工人回報要對得上工單才算 |
| 什麼時候用 | 對話太長、想換助手、額度用完換帳號 | 大任務拆給多個助手一起做 |
| 目前限制 | 只有電腦版；已知問題：Codex 開啟時如果跳出自動更新，交接內容會不見（#18153） | 一清空就全沒了，也不能跨電腦 |

- **重點：額度用完時，真正派得上用場的是「接手對話」**——換帳號，再把內容帶過去。
  分工調度解決的是「怎麼分工」，不是「額度用完怎麼續」

## 投影片 9｜能取代記憶系統嗎？
- **不能。** Orca 只記「這次工作的進度」，按一下清空就沒了，也不會跟著換電腦
- Claude 的 `CLAUDE.md`、Codex 的 `AGENTS.md` 這類記憶檔，官方說 Orca「不碰，那是助手自己的」，只是讓你在介面裡方便打開來改
- 簡單分：Orca 管「**現在**誰在做什麼」；記憶系統管「**以前**學到了什麼」
- **auto-memory 是什麼：** Claude Code 會自動把學到的事記下來，但只存在我這台電腦的使用者資料夾裡，
  換電腦或重灌就沒了。所以**我自己加了一個步驟**：每次對話結束時自動把它複製到專案裡的 `memory\` 資料夾，
  跟著專案一起存進 git、一起備份。這是我自己的作法，不是 Claude Code 本來就有的功能

| | Orca | llm-wiki＋auto-memory（現在用的） | ai-memory（另一套開源工具） |
|---|---|---|---|
| 能保存多久 | 清空或專案結束就沒了 | 存在 git，永久 | 存在 git，永久 |
| 怎麼記下來 | 要手動下指令 | Claude 自動記，我再自動複製進專案 | 自動記錄對話與操作 |

## 投影片 10｜建議
- **想讓好幾個助手同時做、比較結果** → 值得試
- **主要想解決額度用完自動接手** → **先不要導入**，等相關功能真的上線再說（追蹤清單見最後的備註）
- **記憶**：繼續用現在的作法；除非需要「跨電腦、全自動記錄」，才考慮再加 ai-memory

## 投影片 11｜這次查證學到的
- 第一次查的時候，看到 GitHub 上有相關的程式修改，就以為功能已經能用，其實還沒合併
- 「有人提需求」「有人送修改但還沒合併」「已經合併並正式發布」是三回事；
  要一個一個點進去看狀態，再對照正式版的更新紀錄
