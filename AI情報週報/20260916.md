### Claude Fable 5.1／Mythos 5.1 發布，快取讀取降價 75%

`主推工具動態／成本情報`

**新聞內容**

Anthropic 於 9/1 發表新一代旗艦模型 Claude Fable 5.1（一般開放）與 Claude Mythos 5.1（僅限受信任存取計畫，鎖定資安與生命科學用途），兩者皆支援百萬 token 長文本、可在對話中途動態調整思考力度（effort），並新增內容溯源標記（content provenance）。定價方面，Fable 系列快取讀取（cache read）由每百萬 token 1 美元降至 0.25 美元（−75%），標準輸入／輸出維持 10／50 美元；官方估算一般工作負載成本降約 25%、重度 agentic 工作負載最多降 45%。Cursor 於 9/6 證實 Fable 5.1 在 CursorBench 3.2 以 max effort 模式拿下 73.4%，超越 Fable 5（70.5%）與 Opus 5（70.0%），特別擅長「驗證自己的工作成果」；ai_news 另引「SWE-bench Verified 95.0%、SWE-bench Pro 80.0%」，經查為 Fable 5（6 月）舊分數誤植，Fable 5.1 在 BenchLM 獨立榜單 SWE-bench Pro 為 81.2%，Verified 尚無 5.1 專屬公布值。

**建議後續**

IT 財務窗口請 1 名工程師抽樣近一個月 Claude Code／Cowork 帳單，估算快取讀取占比與新舊價格下的實際月費差異；工程主管指派 1-2 名資深工程師在 Cursor 中切換至 Fable 5.1，於下個 sprint 的困難重構任務記錄 token 成本與一次通過率變化。

### Claude Code 週用量上限 9/14 生效：名為 +25%，實為 −17%

`主推工具動態／成本情報`

**新聞內容**

Anthropic 官方帳號 ClaudeDevs 於 8/29 在 X 宣布，自 9/14 起 Claude Code 標準週用量上限對 Pro、Max、Team 及依席次計費的 Enterprise 方案永久調高 25%。但自 5 月起實施的「臨時加碼 50%」於 9/13 到期，新的「永久 +25%」是相對於加碼前的基準計算，換算後用戶實際可用週額度較加碼期間**少 17%**。ClaudeDevs 隨後在同一串貼文補充承認「相較於今天，這代表 Claude Code 的週用量將減少 17%」，並表示正在研發提升用量可視性與控制度的新功能；開發者社群（含 Theo/t3.gg）批評官方公告用詞「調高」掩蓋了實質減少。9/8 Claude iOS App 新增「用量詳情」按鈕可即時查看 Claude Code 額度消耗。

**為什麼對我們有意義**

程式團隊若大量依賴 Claude Code 處理 agentic coding（多輪重構、長任務、並行 subagent），9/14 起實際配額比上週明顯緊縮，衝刺開發期或版本上線前更容易提早觸頂而中斷工作流；企劃與美術若也透過 Claude Code 處理文件／腳本類任務，同樣受影響。

**建議後續**

工程主管本週內盤點團隊過去 2 週的 Claude Code 實際週用量，評估是否逼近新上限；若常態性吃緊，向處長提案升級至更高階 Enterprise 方案，或搭配 Claude API 依量計費作為溢出備援。

### Claude Code 三週連跳 25 版：沙箱、防護、回歸一次看

`主推工具動態／資安`

**新聞內容**

8/27 至 9/15 間 Claude Code 從 v2.1.248 密集發布至 v2.1.272，資安與治理面的重點變更包括：

1. v2.1.248 新增 `--restricted` 旗標，移除所有可執行指令的內建工具與 WebFetch、檔案工具限制在工作目錄內、忽略所有層級設定檔，提供最小權限沙箱；
2. v2.1.251 第三度修補「權限檢查後 symlink 被置換即可讀寫核准範圍外檔案」漏洞（前兩次為 CVE-2025-59829、CVE-2026-25724），並新增 PreModelSwitch／PostModelSwitch hook 供企業攔截模型切換；
3. v2.1.257 為 auto mode 新增「Containment Escape」規則，雲端 metadata 憑證擷取、egress 規避、跨租戶存取不再自動核准，並修補外掛市集 path-traversal 漏洞；
4. v2.1.259 新增 `managedMcpServers` 集中發布 MCP 設定與 `--permission-prompts none` 無人值守模式，修復多個並行 session 互相覆蓋 `~/.claude.json` 導致 workspace 信任狀態遺失的問題；
5. v2.1.265 讓 Cowork／Desktop 遙測新增 `user.email` 與 `user.groups` 欄位，隨後 v2.1.265–267 連續 3 天出現「強制觸發 Gateway 登入導致自架 API 金鑰失效」「第三方相容端點全面回傳 HTTP 400」「WebFetch 無限期卡住」等回歸，至 v2.1.268 才修復；
6. v2.1.269 新增 `claude plugin eval` 外掛評測框架（6 種評分器）與 Bash 差異檢視，同日 v2.1.270 修復唯讀 git 指令無故要求授權的回歸；
7. v2.1.267 新增 `maxEffortLevel` 可由管理端統一限制思考強度上限（top-level 或個別模型層級）；v2.1.271 新增自動沙盒模式下 Bash／PowerShell 指令可逐指令設定 `allowed_domains` 網域白名單、`omitClaudeMd` 讓外掛 subagent 不繼承 CLAUDE.md。

**為什麼對我們有意義**

這批更新等於 Anthropic 在三週內把「agent 執行邊界」從權限提示層拉到網路層（網域白名單）與訓練面防護（Containment Escape），對已在 CI／auto mode 下跑 Claude Code 的團隊是實質資安強化，但 managed settings 涉及沙箱 TLS、代理、自訂 API 標頭者，可能因新增的核准要求卡住既有自動化流程；v2.1.265–267 的回歸則說明「跟著每日新版升級」有實際風險，需要有版本鎖定策略。遙測新增員工信箱與群組欄位屬個資處理範圍變動，需知會法遵。

**建議後續**

工程主管確認團隊版本不落在 v2.1.265–267、v2.1.269 等已知回歸區間，並訂定「延後 2-3 個版本再升級」的鎖版策略；資安主管評估在自動化流程啟用 `allowed_domains` 白名單與 `--restricted` 模式，IT 評估以 `managedMcpServers` 集中發布內部 MCP 連接器、以 `maxEffortLevel` 控管 token 支出；IT／法遵確認 Cowork／Desktop 遙測新增的員工信箱欄位是否已納入個資盤點。

**來源**：GitHub Releases（anthropics/claude-code）；Claude Code 官方 Changelog；ClaudeCodeLog on X；MarkTechPost（ai_news 8/28、8/29、8/31、9/2、9/3、9/5、9/6、9/9、9/10、9/11、9/12、9/13、9/15）

> 🔍 **查證**：⚠️ 大致屬實，1 處版本號已訂正。以 GitHub Releases 逐版比對：v2.1.248 `--restricted`／`CLAUDE_CODE_RESTRICTED=1`、v2.1.251 symlink 修補與 PreModelSwitch／PostModelSwitch hook、v2.1.257 Containment Escape 與外掛 path-traversal 修補、v2.1.259 `managedMcpServers`／`--permission-prompts none`／並行 session 覆蓋 `~/.claude.json` 修復、v2.1.265 遙測 `user.email`／`user.groups`、v2.1.268 release notes 明載 HTTP 400 回歸「since 2.1.265」，皆與官方原文逐字相符；CVE-2025-59829（v1.0.120，CVSS 6.5）與 CVE-2026-25724（v2.1.7，CVSS 7.5）經 GitHub Advisory Database／CVEDetails 確認皆為 CWE-61 symlink-following 同類漏洞。**訂正**：ai_news 原文將 `maxEffortLevel` 歸在 v2.1.271，官方 release notes 顯示實際首見於 **v2.1.267**（9/9），本條內文已更正；`allowed_domains` 與 `omitClaudeMd` 確為 v2.1.271 新增。另查證日（9/17）最新版已到 v2.1.274。

### agent 執行環境收回企業：Cursor Projects／自架環境、Coder Agent Relay

`主推工具動態／平台治理`

**新聞內容**

Cursor 於 9/2 推出 Self-Hosted Machines（分「My Machines」個人機器與「Team Pools」團隊動態機器池），agent 推論仍在 Cursor 雲端、但工具執行（讀寫檔案、跑指令）改在企業自有機器上，程式碼、build 產物與機密不離開企業網路，並新增 Linux／Mac 上的 Computer Use（操控滑鼠鍵盤與瀏覽器）；9/15 進一步開放透過 AWS（全新 Lambda MicroVMs）、Cloudflare、Coder、Daytona、E2B、Modal、Namespace、Vercel 共 8 家沙盒基礎設施夥伴接入（ai_news 原文列 7 家、漏列 Namespace）。9/10 Cursor 另發布「Projects」測試版（所有付費方案可用）：使用者與單一常駐的「協調 agent（coordinator）」在持久化對話中互動，協調 agent 不寫程式而是規劃、拆派任務給可同時並行上千個的子 agent 再彙整成果，可跨月保留專案脈絡，並可設定「監看 Slack 頻道 bug 回報」「排程任務」「追蹤 PR、CI 一失敗就自動修」，整個 Project 跑在雲端獨立機器即使關筆電也不中斷；官方稱重度用戶合併 PR 數達過去 6 倍、一般新用戶提升 30%。9/15 開發環境廠商 Coder 宣布旗下「Agent Relay」自架執行環境正式支援 Claude Code，程式碼、憑證與 agent 觸碰的資料留在客戶控管的機器、每次執行產生完整稽核紀錄、可設定程序層級網路政策，鎖定金融等高度受監管產業。

**為什麼對我們有意義**

三項更新指向同一趨勢——coding agent 從「被動接受單次提示」變成「常駐、自主監控多個資訊來源、擁有長期大範圍執行權限」的角色，同時廠商也提供把執行環境留在企業網路邊界內的選項。對程式團隊而言，把「監看 PR／CI 自動修復」交給協調 agent 可望減少巡檢時間；對資安團隊而言，自架執行環境直接解決「程式碼與資料離開公司網路」的疑慮，但常駐 agent 可存取哪些 Slack 頻道與 repo 的授權邊界需要重新劃定。Coder 方案是直接針對我們主推工具 Claude Code 的自架選項，可與 Cursor 方案並列比較。

**建議後續**

工程主管指派 1-2 名工程師在非正式 repo 試用 Cursor Projects，實測「追蹤 PR 自動修 CI」與「排程任務」的穩定性；資安與工程主管共同評估將 Cursor Cloud Agents 執行環境改接公司自有 AWS 帳號（Lambda MicroVMs）與 Coder Agent Relay for Claude Code 兩方案，比較稽核紀錄完整度與網路政策彈性，作為「自架 agent 執行環境」選型清單。

### GPT-6 Astra 發布：$10/$50、首個觸發關鍵網路安全門檻的模型

### GitSpawn：7 款 coding agent「開專案即中毒」

`平台治理／資安`

**新聞內容**

資安新創 Manifold Security 於 9/1 發布研究「GitSpawn」，揭露影響 7 款終端機 coding agent（Claude Code、OpenAI Codex、Cursor、Block Goose、阿里 Qwen Code、xAI Grok Build、NousResearch Hermes Agent）共 8 項程式碼執行漏洞。手法是利用 Git 效能設定 `core.fsmonitor`：只要惡意 repo 的 `.git/config` 將此參數指向任意指令，agent 開啟專案時例行執行的 `git status` 就會自動觸發，且完全在 agent 沙盒之外執行、不需使用者確認，甚至可能發生在輸入第一個提示詞或完成登入前；攻擊者只需讓帶 `.git` 目錄的專案以壓縮檔、共用硬碟、雲端同步資料夾或 USB 落地即可。Manifold 9/1 重測時 Claude Code 其中一條路徑已於 v2.1.196 修復，Cursor 與 Goose 也已修補，但 Hermes Agent、Qwen Code、Grok Build 及 Claude Code 的「第二條」執行路徑（透過 `claude ultrareview` 觸發、使用另一個未公開的 git 設定鍵）當時仍未修復；OpenAI 同日針對 Codex 公布 3 項對應 CVE（CVE-2026-19590 `core.hooksPath`、CVE-2026-19592 `core.fsmonitor`、CVE-2026-19593 `attr.tree` clean filter，Codex CLI 0.131.0 起修復）。

**為什麼對我們有意義**

直接牽涉工程團隊每天使用的 Claude Code 與 Cursor——一旦有人從外部來源（客戶範例專案、論壇 demo repo、外包廠商交付壓縮檔）解壓帶 `.git` 目錄的專案並用 coding agent 打開，攻擊者可能無感取得開發機上的 SSH 金鑰、雲端憑證與所有 repo 存取權，風險等級遠高於一般 prompt injection。

**建議後續**

資安與工程主管立即確認公司內 Claude Code、Cursor 版本為修復後版本，並發文提醒工程師「不要用 coding agent 直接開啟來路不明、附帶 `.git` 目錄的專案」；若使用 Grok Build、Qwen Code 或 Hermes Agent，暫緩用其開啟外部專案。查證時需確認 Claude Code「第二條路徑」目前是否已修復。

### Deadbugz：MCP 供應鏈攻擊，呼叫滿 3 次才變臉

`平台治理／資安`

**新聞內容**

Pillar Security 揭露一起進行中的 MCP 伺服器供應鏈攻擊「Deadbugz」。攻擊者以 GitHub 帳號「zellkernel」為投放管道，於 8/10 晚間 74 分鐘內向 23 個不相關的 AI／MCP／開發工具專案送出夾帶惡意 MCP 伺服器的 Pull Request；該伺服器自稱「productivity-suite」，提供文字排版與摘要等看似無害功能，但客戶端呼叫工具滿 3 次後就悄悄置換回傳的 metadata 指令，改為引導 agent 搜尋 SSH 金鑰、AWS 憑證、shell 歷史紀錄與 Kubernetes 設定檔，並要求 agent 對使用者隱瞞。研究人員審查時 23 個 PR 中 19 個已關閉、4 個仍開啟；業界同期彙整另有 3 起新的 MCP 伺服器 CVE。

**為什麼對我們有意義**

與 GitSpawn 屬不同攻擊面但同等嚴重——Deadbugz 鎖定的是 Claude Code、Cursor 普遍使用的 MCP 擴充生態系本身，且「用滿 3 次才變臉」的延遲觸發設計，代表工程團隊即使導入前簡單試用過某個 MCP 伺服器，也可能因測試次數不足而誤判為安全，是比已知漏洞更難靠人工審查抓到的風險型態。

## 法規合規

### 歐盟 AI 法案第 50 條：遊戲商店頁與行銷素材 12/2 前須標示 AI

`平台治理／合規（美術／企劃／法務）`

**新聞內容**

歐盟《AI 法案》第 50 條「透明度義務」已於 8/2 正式生效，要求 AI 系統的提供者與部署者對特定 AI 生成或處理過的內容進行揭露；生成式 AI 系統的具體標記（marking）要求則有較長緩衝期，提供者須在 12/2 前完成合規。對遊戲產業而言，法規對「即時、稍縱即逝且不會被錄製或再傳播」的遊戲內容（如即時生成的 NPC 對話、程序化場景）設有例外，只要技術上無法標記且透過遊戲內揭露讓玩家知悉即可；但「藝術作品」例外僅是「減輕」而非「免除」揭露義務，行銷素材與商店頁面（如 Steam 商店頁）並不享有同樣寬鬆待遇，仍須明確標示 AI 生成內容。違規最高可處 1,500 萬歐元或全球年營業額 3%（取較高者），且不限歐盟公司——只要產品有賣給歐盟玩家即受規範。Google Cloud 遊戲業務總監 Jack Buser 於 8/31 稱「約九成遊戲開發者已在用 AI」但多數未對玩家公開說明，凸顯揭露壓力。

**為什麼對我們有意義**

若公司遊戲有在 Steam 或其他管道對歐盟玩家販售，且美術／企劃團隊已經或計畫使用 AI 生成美術素材、行銷預告片或過場動畫（對照 8/27 週報《Vapor World》AI 過場動畫負評案例），現在起商店頁面與行銷素材中的 AI 生成內容都必須明確標示，這不只是玩家觀感問題，更是有罰則的法律義務；12/2 的標記技術規範緩衝期距今不到 3 個月，需要提前確認素材產線是否能配合輸出標記中繼資料（本期 Claude Fable 5.1 新增的 content provenance 標記可能是相關工具之一）。

**建議後續**

法務／發行部門盤點目前販售至歐盟地區的遊戲清單，以及其行銷素材、商店頁面中 AI 生成內容的使用範圍，於 12/2 前確認美術與行銷團隊的產出流程能否加入 AI 生成標示，必要時參考歐盟 AI 辦公室的自願性行為準則（Code of Practice on Transparency of AI-Generated Content）作為合規範本。

**來源**：Cooley（法律事務所解析）；Production Alchemist；Gizmodo；PCGamesN；wccftech（ai_news 8/30、9/1）

> 🔍 **查證**：✅ 確認屬實。Cooley（8/3）、artificialintelligenceact.eu、Faegre Drinker、Paul Weiss 確認第 50 條 8/2/2026 生效、8/2 前已上市的生成式 AI 系統標記緩衝至 12/2/2026；Bird & Bird、SearchEngineJournal 確認執委會最終指引對遊戲等藝術／虛構作品僅「減輕揭露方式」（可置於片尾／載入畫面）而非豁免且解釋從嚴；82dash、DGLaw、Production Alchemist 確認商店頁截圖／關鍵美術／廣告素材屬商業性質不繼承例外；Shibolet、Holistic AI 確認罰則 1,500 萬歐元或全球營收 3%；Faegre Drinker 與執委會官網確認「Code of Practice on Transparency of AI-Generated Content」存在且簽署可產生合規推定。Gizmodo（Kyle Barr，8/31）確認 Jack Buser「roughly nine out of ten」原文。
