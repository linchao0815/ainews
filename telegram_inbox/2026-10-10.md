我最近發現派工有一個會浪費 token 的機制 ⬇️

就是在「主對話」派出「子對話」去工作後，
當「子對話」任務完成時會回報任務結果。
但是 Claude Code 的機制中有一條規定
就是 ✴️ 不能用 SendMessage (tool call) 結束一輪對話 ✴️
所以即使最後一步是回報結果，
回報後必須還要再 request 一次 API，
也就是會浪費一次整個 context 的 token！

所以我做了一個 Mod 給「子對話」
解法是： 把「送件」從模型手上移到 mod。

1️⃣「子對話」會把回報寫入回報檔，然後只回一行文字就結束該輪。
以文字結束不需要任何 tool call，所以不會多出 request。

2️⃣ 該輪結束時（turn.complete 事件），mod 在模型外面讀回報檔，比對上次送過的內容，再用 $.session.send 把新增的部分原文送給指揮站

這樣每份回報少跑 2 次 request，以我大部分的任務，約每次省 30 萬 tokens 的 cache read。
