- https://www.threads.com/@sliven0722/post/Ddcn_bCAe83（來源：AI收集，2026-09-19） — 褚崇名 Sliven (@sliven0722) on Threads / 玩家往前跑，AI 就在前面鋪下一段路。

Hugo Duprez 用 Jev 做了一個跑酷遊戲實驗，讓前方的地形隨著遊戲進行即時生成。這次示範的 API 回應時間約 319～375 毫秒，5 次請求的估計總成本約 0.00286 美元。

做法是把玩家的位置、速度、衝刺狀態，以及目前的地形交給 Jev，讓它決定下一段平台的寬度、高度、間距與類型。選項事先定義好，例如平台可以是 2、3 或 5 格寬，中間留 0、1 或 2 格。Jev 負責選，程式再把地形放進遊戲。

所以，這不是 AI 在遊戲途中重新寫程式，也不是憑空生成整個世界。它是在既有素材與規則裡，持續決定前方的路要怎麼接。

傳統演算法同樣能生成關卡，作者也承認這點。他看好的是，更快、更便宜的結構化決策，能讓開發者嘗試把模型接進遊戲過程。至少在這個跑酷原型裡，玩家不必停下來等 AI 想完，成本也相當低。

- https://www.threads.com/@it.oppa.twhk/post/DdbNpCSjx_v（來源：AI收集，2026-09-19） — @it.oppa.twhk on Threads / 【AI 資訊 🤖】不吐廢話！首款「不生成文字」的 AI 模型 Jev 上線 🔥⚡

寫過 Agent 的人都知道：只想讓 LLM 判斷「是或否」或「選擇分類」，它卻常常噴一堆廢話，最後 JSON 還解析失敗！

前 OpenAI 核心研究員創辦的 TypeSafe AI 推出顛覆性模型：Jev。

它打破「LLM 必須聊天」的架構，定位為「System One」決策模型：
1. 零文字生成：不出廢話句子，原生直出型別安全（Type-Safe）結構化數據。
2. 三大原語：支援 Choice（枚舉選擇）、Score（評分）、Boolean（是非），並附精準機率分佈。
3. 200倍極速、400倍便宜：不用逐 Token 吐字，平行評估多條件，延遲與成本雙雙暴降！

完美適用於 Agent 工具路由、安全審查與分類系統。

💡 歐爸觀點：
AI 不該只有「慢吞吞寫散文」的慢思模式。未來架構一定是 Jev 負責毫秒級直覺決策，大模型負責深度推理，各司其職才是正解！
