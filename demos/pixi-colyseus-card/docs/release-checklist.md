# 發佈與上架前檢查清單

本清單改寫自 [Claude-Code-Game-Studios](https://github.com/Donchitos/Claude-Code-Game-Studios)（MIT，commit `b21fa0f`）的 `release-checklist` 和 `launch-checklist` 兩個技能。原本的主機、Steam、行銷、各部門簽核等段落已刪除，另外補上本專案（網頁版 + Capacitor App + Colyseus）特有的項目。標註 ★ 的項目是本專案驗證或研究時發現的。

**判定規則（沿用原文）**：每一項只能是「通過」「不通過」或「**未評估（NOT ASSESSED）**」。沒有檢查過的項目一律寫「未評估」，**不能當作通過**。只要有任何一項不通過，整體結論就是 NOT READY。

## 1. 建置

- [ ] 從打了 tag 的 commit，可以重現同一份建置結果：`npm ci` 之後 `npm run build`。
- [ ] 版本號已更新，包括 `package.json`，以及 Android 的 `versionCode`／`versionName`、iOS 的 `CFBundleShortVersionString`。
- [ ] ★ 打包大小在預算內。驗證時主程式約 974 KB（gzip 壓縮後 308 KB），應該先拆檔再設定預算。
- [ ] 所有資源都能正常載入：Spine 素材、音效、字型。
- [ ] `npm run test:e2e` 在正式建置（`npm run preview`）上 `ALL PASS`。

## 2. 程式品質

- [ ] TODO、FIXME 數量為 0；保留的要寫明原因。
- [ ] 正式版沒有除錯輸出，也沒有寫死的開發用設定（例如 `localhost`）。
- [ ] ★ **測試掛鉤 `window.__demo`（含 `rawSend`）在正式版要關閉**，或只在測試建置中開啟。目前它在正式版也存在。
- [ ] 所有重要流程都有錯誤處理：斷線、伺服器沒有回應、音效載入失敗。
- [ ] 已接上當機回報（crash reporting），並確認回報真的收得到。

## 3. 資安與伺服器權威

- [ ] 原始碼裡沒有 API 金鑰或任何憑證。
- [ ] 連線一律加密：前端用 `wss://`，伺服器前面放反向代理處理 TLS，憑證要是正式受信任的。
- [ ] 伺服器的每一種訊息，都會檢查格式、遊戲階段和送出者；不合法就拒絕並記錄（見 AGENTS.md）。
- [ ] ★ 防作弊的 e2e 檢查全部通過：自稱獲勝、竄改牌面、重複按準備，都會被伺服器拒絕。
- [ ] 隱藏資訊不會外洩：對手的手牌不會出現在瀏覽器收到的資料裡（StateView 檢查）。
- [ ] ★ `npm audit --omit=dev` 沒有未處理的中、高風險漏洞。驗證時有 `elliptic`、`uuid` 兩項待處理。
- [ ] 拒絕記錄要限制頻率，避免有人刻意大量送錯誤訊息，灌爆日誌。

## 4. 手機版（Capacitor）

- [ ] 符合各商店的審核規範。★ Apple App Review Guidelines 要特別注意以下幾條：
  - [ ] **4.2**：App 不能只是把網頁包一層殼，要有 App 才有的功能、內容或介面。
  - [ ] **2.5.2**：熱更新（不經商店審核就更新程式）只能用來修正錯誤，**不能用來新增或改變功能**。
  - [ ] **5.3.3**：如果有真錢遊戲或博彩性質，要在當地取得執照、限定可用地區，而且 App 本身必須免費。
- [ ] 要求的每一項權限都有說明用途；沒用到的權限不要申請。
- [ ] 已附上隱私權政策連結；Google Play 的資料安全表單、Apple 的隱私標籤都已填好。
- [ ] 在多種尺寸的螢幕上測過觸控，按鈕至少 44×44 CSS 像素（見 `card-game-design` 技能）；瀏海、圓角的安全區沒有遮住內容。
- [ ] 切到背景、再回到前景、App 被系統關閉之後，都會正確重新連線或回到正確的畫面。
- [ ] ★ 至少在一台低階 Android 手機上實測過：WebGL 畫面資源被系統收回（context loss）之後能恢復，FPS 也可以接受。
- [ ] 安裝檔大小沒有超過商店上限。
- [ ] 如果有應用程式內購買，購買流程已測試。

## 5. 商店與上架資料

- [ ] 商店頁的說明文字和截圖都是最新版本，並符合各平台要求的解析度。
- [ ] 已取得年齡分級；★ 有博彩性質的話，要確認各地區的法規。
- [ ] 第三方授權都已列出，包括 MIT、Apache-2.0 的套件，★ 以及 Spine 的商業授權（見研究筆記第十四節）。

## 6. 上線準備

- [ ] 已確認使用數據和錯誤回報都有收到資料。
- [ ] 上線後 72 小時內，有人負責處理問題。
- [ ] 已寫好回滾計畫：要退回哪一版伺服器、哪一版 App，以及熱更新怎麼撤回。
- [ ] 已用接近正式上線的連線數做過壓力測試。
- [ ] 邊界情況都測過：儲存空間不足、網路斷線、App 暫停後恢復。
