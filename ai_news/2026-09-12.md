1. **主推工具動態｜Cursor推出「Projects」測試版：協調agent可在雲端長期運作，還能自動盯Slack、排程與PR**
   新聞內容：Cursor於9月10日發布全新功能「Projects」測試版，開放給所有付費方案（最低20美元/月）用戶。與過去每個任務開一個新對話不同，使用者改為在單一持久化對話中與一個「協調agent（coordinator agent）」互動——協調agent本身不寫程式，而是負責規劃工作、把任務拆給多個子agent（subagent）並行執行，再把完成的成果彙整回來給使用者確認；官方宣稱可同時調度上千個子agent，並讓專案脈絡橫跨數個月持續累積不丟失。更關鍵的是自動化能力：可設定協調agent「監看某個Slack頻道回報的bug」「按排程定期執行任務」「追蹤所有PR、CI一失敗就自動修」，且整個Project運行在雲端自己的獨立機器上，即使使用者關閉筆電也不會中斷。
   為什麼對我們有意義：這代表coding agent的角色正從「被動接受單次提示」轉變為「主動監控多個資訊來源、自行決定何時該做事」的常駐自動化角色，對程式團隊而言，若能把「監看PR/CI失敗自動修復」「追蹤Slack回報的bug」交給協調agent處理，可望減少工程師手動巡檢與交辦子任務的時間；但這也代表agent將擁有更長期、更大範圍的自主執行權限，資安團隊需要重新評估「常駐雲端agent可存取哪些內部系統」的授權邊界。
   建議後續：工程主管可指派1-2名工程師在非正式repo試用Projects，實測「追蹤PR自動修CI」與「排程任務」兩項功能的穩定性與可控性；資安主管應同步評估此類常駐雲端agent的存取範圍與稽核機制，再決定是否開放連接正式內部系統。
   來源：Cursor官方Changelog（https://cursor.com/changelog/projects）；Cursor官方X貼文（https://x.com/cursor_ai/status/2098162488013455784）

2. **主推工具動態／成本情報｜Claude Enterprise推出「Smart Reports」測試版：自動分析團隊AI用量、成本與可包裝成技能的重複模式**
   新聞內容：Anthropic於9月10日為Claude Enterprise方案客戶推出「smart reports」測試版功能，可自動分析一個團隊實際如何使用Claude——包括完成了哪些工作、實際花費多少成本、哪些工作階段容易卡關（產生摩擦），以及哪些重複出現的操作模式值得被包裝成共用技能（shared skills）供全團隊重複使用。測試期間每個組織每月可免費產生最多10份報告，額度於每月1日重置；官方說明此功能目前不支援已啟用客戶自管加密金鑰（CMEK）、HIPAA設定或Access Transparency的組織。
   為什麼對我們有意義：若公司已用Claude Enterprise方案讓程式、企劃或客服團隊使用Claude，這項功能能直接回答IT財務長期以來難以掌握的問題——「錢實際花在哪些工作上、哪個環節最容易卡住、哪些操作值得標準化」，等於免費附贈一套內部AI使用治理儀表板；對企劃室而言，「值得包裝成共用技能的重複模式」這項分析，也直接對應我們近期持續在推動的SKILL.md技能化工作。
   建議後續：若公司已採用Claude Enterprise方案，IT／財務窗口應本週申請開通smart reports測試版，先針對過去一個月的實際用量跑一次報告，作為下一輪AI預算編列與內部技能標準化的具體參考依據。
   來源：Claude Help Center官方說明（https://support.claude.com/en/articles/16893491-get-started-with-smart-reports）；Claude Platform Release Notes（https://support.claude.com/en/articles/12138966-release-notes）

3. **平台治理／資安｜Claude Managed Agents新增「auto」權限模式：讓伺服器自動判斷是否放行agent的每一次工具呼叫**
   新聞內容：Anthropic於9月10日為Claude Developer Platform的Managed Agents功能新增第三種權限政策「auto」。在此模式下，每當agent或其串接的MCP工具要執行一個動作時，改由Anthropic伺服器端逐次評估這次呼叫的風險，自行決定「直接放行執行」「直接拒絕」或「暫停下來、等待人工核准」，取代過去只能「全部自動執行」或「全部要人工核准」兩種極端選項。
   為什麼對我們有意義：若公司工程團隊有使用Claude Managed Agents／API串接內部系統（如玩家資料庫查詢、營運報表產出）自動化流程，過去要嘀在「效率」與「安全」之間二選一——要嘛每個動作都要人工核准拖慢流程，要嘛全部自動執行承擔風險；這次新增的「auto」模式讓伺服器依風險程度動態判斷，等同把「哪些操作可以放行、哪些該暫停」的治理邏輯往前推進一步，但也代表這個判斷邏輯目前掌握在Anthropic端，而非公司自訂規則，資安團隊需要先了解其判斷依據是否符合公司內部風險胃口。
   建議後續：工程主管與資安主管可共同在測試環境試用「auto」權限模式，針對現有or規劃中的Managed Agents自動化流程（如客服工單查詢、報表產出）觀察其放行/拒絕/暫停的判斷是否合理，再評估是否要在正式環境從「人工全核准」切換為「auto」模式以提升效率。
   來源：Claude Platform官方文件（https://platform.claude.com/docs/en/managed-agents/permission-policies）；Claude Platform Managed Agents總覽（https://platform.claude.com/docs/en/managed-agents/overview）

4. **主推工具動態｜Google Antigravity CLI於9/11正式對所有人開放，Gemini CLI功能同步走入尾聲**
   新聞內容：Google於9月11日在官方開發者部落格宣布，Antigravity CLI（原本作為Google Antigravity 2.0桌面版的補充終端機工具）現已正式對所有使用者開放，標誌著公司agent-first開發平台的整合完成；此次公告同時說明，先前以Gemini CLI為主的舊架構將逐步走入尾聲，Gemini CLI／Gemini Code Assist IDE延伸套件先前已於6月18日起停止服務Google AI Pro／Ultra與免費方案用戶的請求。Antigravity CLI以Go語言重寫、執行效能更快更穩定，並保留了Agent Skills、Hooks、Subagents與Extensions（現稱Antigravity plugins）等核心能力，與桌面版共用同一套agent harness與設定。
   為什麼對我們有意義：若公司程式團隊過去以Gemini CLI作為Claude Code／Cursor之外的備援或比較工具，這代表該路線已被官方正式收斂到Antigravity CLI這一套新工具鏈，若團隊尚未完成遷移，可能面臨舊版逐步停止支援後的功能缺口；對於已在評估多家agent供應商以降低廠商依賴度的工程主管，這也是重新盤點「Antigravity CLI是否已具備等同Gemini CLI的核心能力」的時間點。
   建議後續：工程主管確認團隊內是否仍有專案依賴舊版Gemini CLI，若有應規劃於本季內遷移至Antigravity CLI並驗證Agent Skills／Hooks等功能相容性，避免舊工具停止維護後影響既有自動化腳本。
   來源：Google Developers Blog官方公告（https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/）；GitHub（https://github.com/google-antigravity/antigravity-cli）

5. **主推工具動態｜Claude Code本週再跳版至v2.1.269：新增`claude plugin eval`外掛品質評測指令與`/output-style`切換**
   新聞內容：接續9/10發布、修復第三方端點HTTP 400錯誤的v2.1.268（本頻道9/10已報導），Anthropic於9月11日再發布v2.1.269，共98項CLI變更。核心新增功能為`claude plugin eval`指令，可針對一個外掛（plugin）執行其內建的評測套件，產出可重複驗證的量化評分結果（JSON與HTML報告雙格式輸出）；同時新增`/output-style [name]`指令，可列出並切換不同的輸出風格，且此功能延伸支援到Remote Control與雲端／無人值守（headless）等多種session型態；此外Bash工具執行檔案編輯後，現會在結果中直接附上異動內容的diff，讓agent與使用者都能立即看到具體改了什麼。
   為什麼對我們有意義：對已經或計畫自製內部Claude Code外掛（如美術規範檢查、企劃文件範本、程式碼審查技能）的工程與企劃團隊而言，`claude plugin eval`首度提供官方標準化的「外掛品質檢測」工具，能在外掛正式上線前用量化分數驗證其穩定性與正確性，而不必憑經驗判斷；Bash工具內建diff顯示則能讓工程師在agent自動執行腳本、批次修改檔案時，更快速核對實際變更內容，降低誤觸發風險。
   建議後續：工程主管可指派負責維護內部自製外掛的工程師，本週試用`claude plugin eval`為現有外掛建立一套基準評測分數，作為日後外掛版本迭代時的品質把關依據。
   來源：GitHub Release（https://github.com/anthropics/claude-code/releases/tag/v2.1.269）；Claude Code官方Changelog（https://code.claude.com/docs/en/changelog）；X／ClaudeCodeLog（https://x.com/ClaudeCodeLog/status/2098496228455530979）

6. **成本情報｜DeepSeek推出新架構「V4.1-Flash」並調整定價機制，V4-Pro將於9/14起全面轉導此模型**
   新聞內容：DeepSeek於9月10日（UTC時間06:10）在X正式發布「DeepSeek-V4.1-Flash」，是其新一代架構家族中最小的模型，具備原生多模態（視覺理解）能力，採用552B參數的Mixture-of-Experts設計、搭配新的Causal Encoder-Decoder架構（輸入端80億／輸出端160億啟用參數）。定價方面，V4.1-Flash分尖峰／離峰兩種費率：尖峰時段（UTC 01:00-04:00與06:00-10:00）每百萬token輸入0.30美元／輸出1.20美元，離峰時段輸入0.15美元／輸出0.60美元，離峰快取輸入更低至每百萬token僅0.003美元；官方同步宣布舊有的V4-Flash與V4-Flash-Vision-Exp即日起停用（暫時仍會自動轉導至新模型相容），旗艦款V4-Pro也將於9月14日UTC 04:00起全面改路由至V4.1-Flash計費，官方測試顯示新模型在效能、成本、速度與總執行時間上都優於舊版V4-Pro。
   為什麼對我們有意義：若公司工程或企劃團隊已在評估或使用DeepSeek系列模型作為低成本輔助選項（如客服草稿、資料整理、批次內容生成），9/14的自動轉導意味著即使不主動更換模型名稱，實際計費模型與費率也會被動改變，需要重新核對帳單是否符合預期；離峰時段大幅降價（尤其快取輸入僅0.003美元/百萬token）的分時定價設計，也提供了「把非急迫的批次任務排到離峰時段執行以壓低成本」的具體操作空間。
   建議後續：若工程團隊有串接DeepSeek API，應在9/14轉導生效前確認現有呼叫是否指向V4-Pro，並評估是否需要調整程式邏輯以在離峰時段執行非即時性的批次任務，藉分時定價節省成本。
   來源：DeepSeek官方新聞稿（https://www.deepseek.com/en/news/deepseek-v4-1-flash/）；DeepSeek官方X貼文（https://x.com/deepseek_ai/status/2097930608790167907）
