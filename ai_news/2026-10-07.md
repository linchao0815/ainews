## 1. **主推工具動態／資安｜Claude Code連發v2.1.292、v2.1.293：修補UNC網路路徑讀取繞過權限提示漏洞、Agent工具新增`effort`參數、外掛市集一鍵安裝**
   **新聞內容**：Anthropic於10月6日、10月7日連續發布Claude Code v2.1.292、v2.1.293，延續過去一週幾乎每日迭代的節奏（接續10/6已報導的v2.1.290、v2.1.291）。v2.1.292修補一項具體資安漏洞——先前版本中，透過PreToolUse hook核准、或系統處於auto模式時，讀取Windows網路磁碟機UNC路徑（如`\\server\share\...`）的檔案會直接繞過原本該觸發的權限提示；同版本另修復了macOS／Windows下notebook或PDF讀取可能因連結在讀取過程中被中途替換、而回傳核准範圍外檔案的漏洞，並新增`claude plugin install --marketplace <source>`可一次完成「加入外掛市集＋安裝外掛」、Agent工具新增`effort`參數可指定子agent執行時的思考強度。隔日上線的v2.1.293則聚焦一般性修復與體驗優化，包含修正對話因上下文壓縮而誤判先前動作未完成導致重做、佇列中的訊息因操作被切到背景執行而遺失等問題，並加速Team／Enterprise組織的啟動流程。
   **為什麼對我們有意義**：UNC路徑繞過權限提示是實質可被利用的資安破口——如果工程師在Windows機器上用Claude Code讀取掛載的網路磁碟機（例如共用的美術素材庫、企劃文件伺服器、玩家資料備份區），先前版本可能在使用者未確認的情況下讀取這些受限路徑內容，資安窗口應視為優先修補項目；新增的`effort`參數讓工程主管能針對不同任務精細分級子agent的運算成本（例如簡單格式調整用低effort、複雜重構用高effort），是直接可操作的成本控管手段；外掛市集一鍵安裝則降低團隊導入先前已報導的各類Mods（防刪庫、TDD守門員、派工儀表板等）的操作門檻，有利於資安窗口推動公司標準化設定。
   **建議後續**：資安／IT窗口本週內將所有Windows開發機與CI runner的Claude Code統一升級至v2.1.293以上，並重新驗證既有settings.json的deny規則對UNC路徑讀取仍然有效；工程主管評估在長任務或批次作業中依任務複雜度搭配`effort`參數分級控管成本，並測試`--marketplace`一鍵安裝指令是否能加速已規劃導入的資安類Mods（如先前已報導的防刪庫、金鑰遮罩）全公司標準化部署。
   **來源：**GitHub Release v2.1.292（https://github.com/anthropics/claude-code/releases/tag/v2.1.292）；GitHub Release v2.1.293（https://github.com/anthropics/claude-code/releases/tag/v2.1.293）

## 2. **主推工具動態／成本情報｜Anthropic正式發表Claude Haiku 5.5：百萬token上下文、輸入每百萬token僅0.1美元，同步成為API預設Haiku模型**
   **新聞內容**：Anthropic於今日（10/7）正式發表Claude Haiku 5.5，並透過同日上線的Claude Code v2.1.293同步設為Anthropic API的預設Haiku模型（model ID：`claude-haiku-5-5`）。官方定價為每百萬輸入token 0.10美元、輸出token 0.50美元（適用10萬token以內的prompt），超過10萬token則輸入漲至0.50美元、輸出漲至2.50美元，另支援prompt cache最高省90%、批次處理最高省50%。官方明確列出的建議應用場景包括：高量文字任務（分類、摘要、文字生成）、即時互動場景（聊天、語音agent、即時客服）、由大模型指派任務的coding子agent、瀏覽器／桌面自動化（如表單填寫），以及跨多檔案的簡單程式修改。此次發布使9/22 Opus 5.5、9/28 Sonnet 5.5以來的Claude 5.5系列三款模型全數到齊。
   **為什麼對我們有意義**：百萬token上下文加上目前主流模型中數一數二的低單價，讓Haiku 5.5很適合處理公司內部「量大但不需要頂規推理」的場景——例如客服罐頭回覆初稿產生、玩家申訴初步分類、活動公告多語系格式校對、或大量程式碼檔案的初步掃描摘要；官方明確點名的「coding子agent」與「瀏覽器／桌面自動化」用途，也直接對應本期已報導的claude-mem、Cua等工具情境，可作為搭配使用的低成本執行層。對工程團隊而言，若能把部分現行跑在Sonnet甚至Opus上、但任務複雜度其實不高的批次流程下放到Haiku 5.5，有機會在不明顯犧牲品質的前提下大幅壓低API帳單。
   **建議後續**：工程主管與企劃室／運營窗口共同盤點目前跑在Sonnet 5.5或Opus 5.5、但任務複雜度不高的批次或自動化流程（如格式檢查、簡易分類、摘要產生），抽樣改用Haiku 5.5進行A/B測試，比較輸出品質落差與實際成本節省幅度，再決定是否全面切換。
   **來源：**Anthropic官方（https://www.anthropic.com/claude/haiku）；GitHub Release v2.1.293（https://github.com/anthropics/claude-code/releases/tag/v2.1.293）

## 4. **GitHub趨勢／工具能力（程式／運營QA）（頻道分享）｜開源「e2e」測試框架單日暴增逾1,700星登GitHub trending：一套程式碼同時測網頁與手機App，AI agent照自然英文操作、驗證後自動轉回放**
   **新聞內容**：開發商TesterArmy釋出的開源專案「e2e」（Apache-2.0授權，TypeScript）於10月7日成為GitHub當日漲幅最大專案之一，依同事於Telegram頻道分享的貼文回報為單日新增約1,700顆星；經本日即時查核GitHub trending榜單，24小時內實際新增1,391顆星，累積總星數達7,344顆，與貼文描述大致相符。其核心設計是用自然英文描述使用者操作步驟（例如「登入帳號後點擊購買按鈕」），由AI agent執行後，再用傳統、確定性的程式斷言驗證結果；每個步驟第一次跑通後會把實際操作路徑錄製下來，之後重跑同一測試便直接回放錄好的操作、不再呼叫AI模型，兼顧撰寫彈性與長期執行成本。網頁測試底層採用類似Playwright的定位器語法，手機測試則透過`@e2e-dev/mobile`引擎在iOS模擬器與Android模擬器上執行相同測試腳本，兩者共用同一套測試案例寫法。
   **為什麼對我們有意義**：對QA與程式團隊而言，若公司同時有網頁版（官網、客服後台）與手機App（手遊本體或客服App），過去往往得維護兩套不同框架的自動化測試（如Playwright測網頁、Appium測手機），這款工具主打「一套測試案例、兩邊都能跑」且用自然語言描述操作，可降低撰寫與維護測試腳本的門檻；其「首次跑用AI、之後重跑用錄製回放」設計也控制了長期執行的API費用，不會每次跑回歸測試都重新呼叫模型。但該專案目前仍是1.0版本前的早期階段，API與設定可能變動，且預設會上傳匿名使用遙測資料（指令、引擎與失敗點，不含測試或App內容），導入前應先確認是否符合公司資安規範。
   **建議後續**：QA主管指派1名工程師，以內部一款同時有網頁後台與手機App的小型功能試用e2e框架撰寫跨平台測試案例，評估撰寫效率與回放穩定度是否優於現行Playwright／Appium雙框架維護方式；資安窗口同步確認其預設遙測機制是否需要停用。
   **來源：**Threads／dev（https://www.threads.com/@easyanythinghk/post/DeLxpMJgJo_）；GitHub（https://github.com/tester-army/e2e）

## 5. **GitHub趨勢／工具能力（程式／QA）（頻道分享）｜Rust打造輕量無頭瀏覽器「Moli」衝上1.2萬星：記憶體僅Chrome Headless的十分之一，專為AI agent設計**
   **新聞內容**：開發者Lexmount釋出的開源專案「Moli」是一款以Rust從零打造的瀏覽器引擎（非Chromium包裝），GitHub星數已達約1萬2,300顆、326次fork，採Apache-2.0與MIT雙授權供選用。其設計理念是「agent不需要的渲染工作就不做」：預設只回傳DOM結構與結構化頁面資料，完整版面佈局與像素渲染（screenshot、PDF輸出）都是選用功能，需要時才額外觸發排版與渲染。根據分享貼文引述的開發者實測，Moli待機記憶體占用約73MB，相較headless Chrome的773MB少了約九成；Moli支援Chrome DevTools Protocol，因此Playwright等既有自動化工具可直接改接到其上驅動，另內建MCP伺服器可直接讓agent導航網頁、擷取Markdown格式內容、填寫表單。專案明確聲明不支援GUI瀏覽器模式、GPU合成、像素級還原Chrome顯示效果，或高擬真度的Canvas與媒體播放，需要這類功能的頁面會直接失敗。
   **為什麼對我們有意義**：對程式與QA團隊而言，若有大量agent驅動的網頁抓取、自動化登入測試或商店頁／競品監控需求（與先前已報導的Agent-Reach等工具同屬一類應用），Moli這類「不做多餘渲染」的輕量引擎能大幅降低單一agent任務的記憶體與運算成本，同一台機器上可並行跑更多agent瀏覽器實例，對需要大規模平行化的自動化測試或資料蒐集場景尤其有感；但因其明確不支援像素級精確渲染，若測試項目涉及視覺回歸測試（檢查畫面排版是否跑版），仍需搭配傳統瀏覽器方案並行使用。
   **建議後續**：QA或工程主管指派1名工程師，以現有一套Playwright自動化測試腳本為對象，改接Moli作為底層瀏覽器引擎進行小範圍替換測試，比較記憶體占用與執行速度的實際差異，評估是否能在CI環境中大規模平行化執行測試以縮短回歸測試總時長。
   **來源：**Threads／0xalpha.ai（https://www.threads.com/@0xalpha.ai/post/DeLDra4k-Qp）；GitHub（https://github.com/lexmount/moli）

## 6. **GitHub趨勢／工具能力（程式）｜「claude-mem」持久記憶外掛衝上9.7萬星：自動壓縮session紀錄、跨對話找回脈絡，宣稱省下近9成token**
   **新聞內容**：開發者thedotmack釋出的開源專案「claude-mem」（Apache-2.0授權）是一套讓Claude Code（以及Codex、Cursor、Gemini CLI等）具備跨session持久記憶的外掛，GitHub星數已達約9萬7,665顆、8,600次fork。其運作方式是透過SessionStart、UserPromptSubmit、PostToolUse等五個生命週期hook，記錄agent在對話中實際做了什麼，再用AI將紀錄壓縮成摘要，存進本機SQLite資料庫並搭配向量資料庫（Chroma）做語意加關鍵字混合檢索；下次開新對話時，透過search、timeline、get_observations三個MCP搜尋工具先抓精簡索引、只在真正需要時才取完整細節，官方宣稱此分層檢索設計可節省約10倍的token消耗。專案另提供`<private>`標籤讓使用者可將機敏內容排除在記憶儲存之外，並有選用的雲端同步備份服務；登入官方託管服務「claude-mem observer」享30天免費試用，之後需訂閱或自備API金鑰。
   **為什麼對我們有意義**：這直接對應10/4已報導的「Opus 5.5長任務實戰心法」中提到的痛點——長任務因上下文被壓縮摘要而「失憶」、需要額外維護TASKS.md手動補救；claude-mem等於把這套「長任務記憶管理」自動化、系統化，讓工程師不必每次開新對話都重新解釋專案背景或先前決策，對維護大型重構專案、跨多天進行的遷移任務特別有幫助，也可與本期第2則Haiku 5.5這類低成本子agent搭配使用以控制整體花費。需注意README中含有與軟體功能無關的加密貨幣代幣「CMEM」相關連結，工程主管評估時應聚焦其開源記憶管理核心功能，與該代幣完全脫鉤看待，並優先使用自備API金鑰的離線模式以避免依賴其官方託管訂閱。
   **建議後續**：工程主管指派1至2位常跑長時間重構或遷移任務的工程師，試裝claude-mem的本機離線模式（改用自有API金鑰，不綁定其代幣或訂閱服務），比較套用前後長任務的「忘記脈絡」頻率與實際token花費是否改善，若效果顯著可評估是否納入公司標準設定。
   **來源：**GitHub（https://github.com/thedotmack/claude-mem）

## 7. **GitHub趨勢／工具能力（程式）｜「Cua」開源電腦操作型agent基礎設施站上2.87萬星：一套API跨macOS／Linux／Windows打造agent專用虛擬桌面**
   **新聞內容**：開源專案「Cua」（trycua/cua）提供一整套讓AI agent能實際操作電腦桌面的基礎設施，GitHub星數約2萬8,710顆、2,000次fork，主體以MIT授權釋出（其中「Cua Spaces」桌面應用模組採FSL-1.1-MIT原始碼可閱覽授權，發布兩年後自動轉為MIT）。專案組成包括：「Cua Spaces」提供可在自有機器或雲端帳號上運行的完整macOS／Linux／Windows桌面環境供agent操作；「Cua Driver」讓agent透過CLI、MCP或SDK檢視與操控macOS、Windows、Linux上的原生應用程式與瀏覽器；「Lume」用於在Apple Silicon上建立與管理本機macOS/Linux虛擬機；以及「Cua Bench」可建立電腦操作任務、評估agent表現並匯出訓練用的操作軌跡資料。此專案與10/2已報導的NVIDIA Open Agent Safety Platform、10/6已報導的Microsoft Copilot Studio Computer Use同屬「讓agent操作電腦桌面」技術方向，但Cua定位是提供開發者自建此類agent的底層基礎設施，而非前兩者的治理／安全防護層。
   **為什麼對我們有意義**：對程式與QA團隊而言，Cua提供了一套現成的「agent專屬虛擬桌面」開發框架，若未來想自建能操作內部後台系統、跑Windows/macOS桌面應用回歸測試、或自動化處理只有GUI操作、沒有API的舊系統（例如某些僅有桌面客戶端的內部工具），可以此為起點而不必從零打造沙盒與操作介面；其「Cua Bench」評估與訓練資料匯出功能，對未來若考慮微調自有電腦操作agent也有參考價值。但因是自架開源基礎設施而非商用服務，仍需工程團隊自行承擔維運與安全加固責任，不像NVIDIA OpenShell或Microsoft方案內建治理層，導入前應自行補上存取範圍限制。
   **建議後續**：工程主管指派1名工程師在非正式環境試架Cua Spaces，針對一個現有「僅能透過桌面GUI操作、沒有API」的內部舊系統，評估能否用agent自動化其中重複性高的操作流程；同時比照10/2已報導的OpenShell政策式沙盒概念，規劃為自架的Cua環境補上明確的存取範圍限制。
