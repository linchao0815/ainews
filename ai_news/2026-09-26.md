## 1. **主推工具動態｜Claude Code v2.1.283：新增模型鎖定管控`deniedModels`／`availableModelsMatch`與原生`/doctor prompt-audit`健檢指令**
   **新聞內容**：Anthropic於9/25發布Claude Code v2.1.283，新增三項功能：其一，新增`x-claude-code-prompt-id`閘道提示標頭（需設定環境變數`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`啟用），讓企業自架的LLM gateway能把同一個使用者提示產生的所有請求歸為一組，方便做成本與用量歸屬；其二，新增managed settings `availableModelsMatch: "exact"`（把可用模型鎖定在指定的確切版本，阻擋新模型發布時被自動悄悄升級）與`deniedModels`（可直接硬性封鎖特定模型，即使該模型原本被允許使用）；其三，新增內建的`/doctor prompt-audit`（亦稱`/checkup prompt-audit`）指令，可掃描CLAUDE.md、skills、agents與commands，揪出專為舊世代模型寫的過時prompt寫法。開發者daniel_mac8在X上分享實測結果，指該指令一次掃描出約70處過時的prompt反模式。與9/23已報導的Lance Martin個人`/claude-api prompt-audit` skill不同，這次是Anthropic官方直接把同類健檢功能內建進Claude Code核心的`/doctor`指令，不需另外安裝第三方skill。
   **為什麼對我們有意義**：`deniedModels`與`availableModelsMatch: "exact"`讓IT/工程主管能鎖定公司內各團隊實際可呼叫的模型版本，避免新模型上線時被自動切換導致預算或行為不可預期地變動，對統一管理多個開發／企劃團隊的模型使用政策是直接可用的治理工具；閘道提示標頭則對已自架LLM gateway做成本歸屬的公司有實質幫助。官方內建的`/doctor prompt-audit`功能等於免費提供了CLAUDE.md／skills瘦身健檢，若團隊尚未跑過9/23報導的第三方版本，現在可以直接用官方原生指令替代。
   **建議後續**：工程主管本週在測試環境對現有CLAUDE.md與team skills執行一次官方`/doctor prompt-audit`，比對9/23若已跑過第三方版本的結果差異；IT主管評估是否要在企業範本中預設啟用`availableModelsMatch: "exact"`與`deniedModels`，統一鎖定各團隊可用的模型版本與預算範圍。
   **來源：**GitHub Release（https://github.com/anthropics/claude-code/releases/tag/v2.1.283）；Claude Code Docs Changelog（https://code.claude.com/docs/en/changelog）；Lance Martin on X（https://x.com/RLanceMartin/status/2102575471502528989）；daniel_mac8 on X（https://x.com/daniel_mac8/status/2102866663997952076）

## 2. **主推工具動態／工具能力（程式）｜Anthropic開放Claude Plugins官方市集投稿入口，MCP用量年增110倍**
   **新聞內容**：Anthropic於9/25開放公開投稿入口，讓付費方案的開發者可以把自製的MCP connector與Agent Skill套件（以GitHub repo託管）提交進官方Claude Plugins目錄，並提供審核狀態追蹤與使用分析數據；同一篇公告中Anthropic揭露，Claude系列產品今年MCP用量成長達110倍。開發者社群帳號AGTP在X上發布詳細解讀貼文說明投稿流程與審核機制。
   **為什麼對我們有意義**：目前公司內部若有程式或企劃團隊已經寫好一些內部pipeline skill（例如美術素材批次處理、build自動化、QA測試腳本），這次開放的官方投稿管道提供了一個比自建repo更受信任、有審核與用量分析的正式發佈管道，即使暫時只想內部使用而非公開分享，也可以參考官方審核標準來規範內部skill的品質；MCP用量年增110倍則反映Claude生態系的第三方整合正快速擴張，值得工程主管留意是否有現成的官方或社群MCP connector可以直接採用，減少重複造輪子。
   **建議後續**：工程主管盤點目前團隊內部已有的Claude Code skills／MCP connector，評估其中是否有值得整理後投稿進官方目錄的候選（即使先以私有／內部方式使用），並參考官方審核標準作為內部skill品質基準。
   **來源：**Claude官方部落格（https://claude.com/blog/build-plugins-for-claude）；AGTP on X（https://x.com/AGTPinsights/status/2103608180970594532）；Unite.AI（https://www.unite.ai/anthropic-opens-directory-submission-portal-for-claude-plugins/）

## 3. **主推工具動態(輔)｜Google Antigravity CLI新增`/plan`指令與「Plan Review Policy」：agent動手前先審計畫**
   **新聞內容**：Google於9/25對Antigravity CLI（本頻道9/24已報導其全面公開開放）新增`/plan`指令，讓agent在真正動手寫程式或修改檔案前，先產出一份可編輯、可審閱的執行計畫；同時新增管理員層級的「Plan Review Policy」設定，可選擇「每次都要求人工審閱計畫」「僅在agent自己判定計畫值得審閱時才詢問」或「完全略過審閱直接執行」三種模式。
   **為什麼對我們有意義**：對已評估或小規模導入Antigravity CLI作為Claude Code輔助工具的工程團隊而言，這項設定是一個實質的防呆機制——尤其若agent操作對象涉及正式環境的build腳本或live-ops設定檔，IT/資安主管可以強制要求「每次都要人工審閱計畫」，在不完全禁用agentic coding的前提下，降低agent誤操作造成的風險。
   **建議後續**：目前有試用Antigravity CLI的團隊，可先在管理員設定中將Plan Review Policy調整為「每次審閱」模式，並實測`/plan`產出的計畫是否足夠清楚易懂，評估是否適合套用在涉及正式環境操作的工作流程上。
   **來源：**Releasebot Antigravity更新追蹤（https://releasebot.io/updates/google/antigravity）；Gradually.ai Antigravity Changelog（https://www.gradually.ai/en/changelogs/antigravity/）

## 4. **平台治理／成本情報｜微軟大改版Copilot：Home／Code／Autopilot三合一，常駐背景agent「Autopilot」改按用量計費**
   **新聞內容**：微軟於9/25發布重新設計的Copilot App，整合為三大區塊：「Home」內建Chat、Cowork與Office三件套；「Code」提供類似GitHub Copilot的建置工具；「Autopilot」（前身為6/2發布的代號「Scout」）具備自己的Entra身分與長期記憶，即使沒有人在使用時也會持續在背景執行任務。計費模式隨之改變：一般Copilot聊天維持既有的每人授權訂閱制，但Autopilot這類agent功能改成「用量計費」，其私人預覽版將於9月底擴大開放。微軟執行長Satya Nadella親自在X上發文，將此次改版形容為「a new OS for work」。
   **為什麼對我們有意義**：若公司已採用Microsoft 365生態系，這是主要生產力平台商首次把「持續在背景自主運作的agent」正式產品化並獨立計費，直接影響IT預算規劃——用量計費模式代表若Autopilot被大量或不當觸發，帳單可能難以預估；同時Autopilot擁有獨立的Entra身分，資安/IT團隊需要把它比照一般員工帳號，納入既有的IAM權限管理與稽核範圍，而不能假設它只是聊天工具的延伸。
   **建議後續**：IT主管在Autopilot私人預覽擴大開放後，先申請小範圍試用並嚴格設定用量上限與存取範圍，評估實際帳單與既有Copilot訂閱费用的疊加效果；資安負責人同步確認Autopilot的Entra身分是否已被納入公司現有的身分治理與稽核流程。
   **來源：**微軟官方部落格（https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/）；VentureBeat（https://venturebeat.com/technology/microsoft-revamps-its-copilot-ai-with-a-persistent-autopilot-agent-and-hosting-for-ai-generated-apps）；VentureBeat on X（https://x.com/VentureBeat/status/2103454572735795609）；FirstSquawk on X（https://x.com/FirstSquawk/status/2103456005925531841）

## 6. **成本情報｜韓國Liner發布「Model API」自動路由至最便宜可用模型，官方稱內部token支出降逾50%**
   **新聞內容**：韓國AI公司Liner於9/15宣布、9/24公布具體定價的「Liner Model API」是一個模型路由層服務，會依每次請求需求自動挑選成本最低但仍能勝任的模型執行，而非固定綁死單一模型。公布的定價為每百萬輸入token 1美元、輸出token 6美元、快取輸入token 0.10美元。Liner官方表示，自家內部在8月導入此路由機制後，token支出較今年上半年下降超過50%。
   **為什麼對我們有意義**：這是一個附帶具體定價與實測降本數據的「多模型自動路由」案例，若公司IT/財務團隊正在評估是否要從單一綁定Claude的模式，改為視任務難度自動切換到較便宜模型的路由策略（呼應本頻道9/19已報導的Jev路由外掛概念），Liner這組真實定價與內部省錢數字可作為評估路由策略投資報酬率的具體基準點；尤其對程式與企劃團隊大量批次呼叫、任務難度落差大的場景（如客服工單分類 vs. 複雜程式除錯），路由策略的潛在節省效果可能相當可觀。
   **建議後續**：IT／財務窗口將Liner Model API的定價與降本數據，併入公司現有的模型路由策略評估資料（可與9/19已報導的jev-codex-router概念比較），評估是否值得在非核心批次任務上小規模試驗自動路由機制。
   **來源：**GlobeNewswire（https://www.globenewswire.com/news-release/2026/09/24/3368253/0/en/liner-launches-liner-model-api-to-cut-enterprise-llm-costs-by-more-than-50.html）；Liner官方公告（https://liner.com/news/liner-model-api）

## 7. **GitHub趨勢／工具能力（程式）｜「AI agent團隊」管理平台paperclip衝上逾8萬星，直擊agent艦隊治理痛點**
   **新聞內容**：開源專案`paperclipai/paperclip`是一款針對「管理一整組AI agent團隊」而非單一coding agent設計的開源平台，提供類似組織圖的agent角色配置、預算控管與治理、跨agent的成本追蹤等功能。根據追蹤報導，該專案星數於9/24已突破約8.1萬顆，截至9/26查證時部分來源顯示已來到約8.7萬顆。
   **為什麼對我們有意義**：隨著我們程式團隊可能同時運作多支專職coding／測試／審查agent（本頻道近期已報導多款單一agent強化工具，如9/23的Superpowers、9/25的Unreal-MCP），管理多個agent各自的權限、預算與任務分派會逐漸變成新的治理痛點——市場研究機構Gartner即指出，agentic工作流程每個任務消耗的token量可達傳統做法的5至30倍。paperclip這類開源「agent團隊管理」工具，對工程主管evaluate如何統一管控多agent艦隊的成本與權限，提供了一個具體可試裝的參考對象。
   **建議後續**：工程主管可請1名同仁在測試環境試裝paperclip，評估其對公司內部多agent工作流程（例如coding agent＋審查agent＋測試agent的組合）的預算與權限管控效果，若可行可作為下一階段agent治理基礎建設的候選方案之一。
   **來源：**GitHub - paperclipai/paperclip（https://github.com/paperclipai/paperclip）；Indie Hackers（https://www.indiehackers.com/post/how-i-built-an-open-source-ai-agent-platform-that-hit-73k-github-stars-and-what-i-learned-about-building-in-public-1a56644a47）

## 8. **GitHub趨勢／工具能力（程式）｜獨立於ai-memory之外的agent長期記憶新秀「hindsight」單日暴增逾1,600星**
   **新聞內容**：`vectorize-io/hindsight`是一款專注於agent「長期學習型記憶」的開源專案，與本頻道9/22已報導、以Git管理Markdown wiki為核心的「ai-memory」屬不同技術路線——hindsight強調的是讓agent能從過往互動中持續學習調整行為，而非單純把架構決策記錄成可檢索的文件。根據GitHub趨勢追蹤紀錄，該專案截至9/25-26已累積約2.35萬顆星，單日新增星數達1,668顆，是近期追蹤到的最高單日成長量之一。
   **為什麼對我們有意義**：對我們程式團隊而言，若已經評估過9/22報導的ai-memory用於「跨agent換手不必重講背景」的場景，hindsight提供了另一種技術路線的比較對象——著重「行為隨時間學習調整」而非單純的背景文件檢索，可能更適合長時間運行的coding agent session或未來若企劃／程式團隊嘗試把類似機制用在NPC行為agent上的場景；兩者定位不同，值得工程團隊視實際需求（背景還原 vs. 行為學習）分別評估。
   **建議後續**：已試裝過ai-memory的工程師可額外評估hindsight在同一測試專案上的表現，比較兩種記憶機制在長時間coding agent session中的實際效果差異，作為後續選型參考。
   **來源：**GitHub - vectorize-io/hindsight（https://github.com/vectorize-io/hindsight）；agents-radar Issue #206（https://github.com/kouweizhu/agents-radar/issues/206）；github-trending Issue #1503（https://github.com/web1992/github-trending/issues/1503）

## 9. **工具能力（程式，頻道分享）｜Apple「fm」CLI查證屬實：macOS 27內建本機AI對話工具，免API金鑰、免雲端**
   **新聞內容**（頻道分享）：同事透過Telegram頻道「AI收集」分享的Threads貼文（@5min_ai）指出，macOS 27已內建一個可透過終端機指令`fm`直接對話的本機AI模型（Apple Foundation Model），例如`fm chat`可直接開始對話、`fm respond --image`可處理圖片辨識，加上`--model pcc`參數可選擇改走Apple的Private Cloud Compute而非純本機運算；經WebSearch交叉查證，此功能確實存在且已於WWDC26 Session 334（「Build AI-powered scripts with the fm CLI and Python SDK」）正式發表，隨macOS 27（目前為beta版，預計今年秋季正式釋出）內建。惟原貼文提到的`sudo fm license`指令，查無任何官方或第三方文件佐證，較可能是把Apple Intelligence／模型授權同意提示誤記成獨立指令，此細節建議實測前先行留意；此外已有第三方開發者釋出回植（backport）版本（如`brianwestphal/apple-fm`、`kosminus/fm`），讓還在用macOS 26的使用者現在就能體驗類似的本機對話功能，不必等macOS 27正式版。
   **為什麼對我們有意義**：對程式與QA團隊而言，這是一個完全免API金鑰、免雲端費用、資料不出本機的輕量AI對話/圖片辨識工具，適合拿來做內部原型測試、批次文字或圖片初步標記（例如美術素材粗略分類、QA腳本輔助）等不需要高階模型能力、但希望避免雲端API成本或資料外流疑慮的小型任務；但因macOS 27目前仍是beta版，指令細節（如貼文誤傳的`sudo fm license`）需要實測時自行核實，且本機小模型的能力上限目前尚缺乏公司內部的具體驗證。
   **建議後續**：若團隊內有使用Mac開發環境的工程師或QA人員，可先用第三方backport版本（如`apple-fm`）在macOS 26上小規模試用`fm chat`／`fm respond --image`，評估本機模型在低風險分類任務上的實用度與限制，作為之後macOS 27正式版上線的參考。
