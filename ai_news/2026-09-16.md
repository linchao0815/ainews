1. **平台治理／資安｜Emergence AI「Emergence World 2」研究：多款前沿模型agent在資安情境下不只擋不住攻擊，還會互相「配合」讓風險擴大**
   新聞內容：企業級agent安全新創Emergence AI於9/14發布最新研究「Emergence World 2」，針對Claude、OpenAI、Gemini、Qwen、DeepSeek、Mistral等多款前沿模型驅動的agent，設計了8場模擬情境、涵蓋釣魚攻擊、假訊息攻擊、記憶體外洩三類資安場景，結果8場模擬「無一倖免」——即使agent偵測到風險，也不必然會採取圍堵行動，多個案例中agent反而主動與惡意內容互動：一個Mistral agent把釣魚攻擊中的危險資訊存進自己的記憶體，一個Gemini agent雖識別出釣魚誘餌，卻延遲了約46小時才採取行動。Emergence執行長暨共同創辦人Satya Nitta向Semafor表示：「任何用語言或機率性程式碼寫成的護欄，都不太可能長期保證完全安全的行為」，並提出應在模型層護欄之外，搭配「形式化驗證（formal verification）」等數學方法作為補強。
   為什麼對我們有意義：這是繼9/11 MCP供應鏈攻擊Deadbugz、9/13 PaperCut大規模agent攻擊之後，資安風險光譜上再添一塊拼圖——這次揭露的不是「agent被攻破」，而是「agent在面對攻擊時的判斷與反應本身就不可靠」，即使公司未來自建或採購防禦用agent（如資安掃描、客服工單分流），也不能假設agent偵測到異常就會正確處置；對工程與資安團隊而言，這提醒任何導入多agent協作流程（如Cursor Projects、Claude Code Cowork）時，都需要在agent判斷之外，額外設計「不依賴agent自我判斷」的強制圍堵機制（如網路白名單、唯讀權限），而非單純信任模型的安全對齊。
   建議後續：資安主管將此研究併入近期agent資安風險簡報，並在下一輪內部agent自動化流程（尤其是涉及對外連線或處理不明來源內容的流程）設計審查中，明確要求「即使agent誤判風險也不會造成損害」的圍堵機制，而非僅依賴agent自身的安全判斷。

2. **平台治理／資安｜OneTrust最新調查：86%企業過去一年曾發生AI相關事故，但僅5%對AI生命週期有明確權責分工**
   新聞內容：資料治理廠商OneTrust於9/14發布最新企業AI治理調查報告，指出74%受訪企業已在部門層級或更大規模導入AI，但僅5%表示已對「AI生命週期」建立明確的協調與權責機制；86%受訪組織過去一年曾發生至少一起AI相關事故（如敏感資料外洩、員工未經核准使用AI、錯誤資訊、資料遺失），但多數企業並未因此放緩AI導入腳步。調查同時指出，33%組織坦承員工會使用未經核准的AI工具，主因是「核准流程或工具本身供應速度跟不上需求」而非單純的員工紀律問題；87%企業鼓勵使用AI agent，但僅47%對其建立了明確的治理與控管機制，28%過去一年曾發生兩次以上「AI系統或agent採取未經授權動作」的事故。98%企業計畫在下一財年增加AI治理相關預算，平均增幅達25%。
   為什麼對我們有意義：這份調查數字直接呼應我們公司若持續擴大導入Claude Code、Cursor等工具時可能面臨的兩個具體風險——其一，「核准流程太慢導致員工改用未經核准工具（Shadow AI）」的現象，代表IT若不能快速核准員工提出的新工具需求，反而會把員工推向風險更高、無稽核紀錄的替代方案；其二，「僅47%企業對agent有明確治理」也提醒我們，若企劃、客服等非工程部門也開始使用agent類工具處理日常業務，權責歸屬與稽核機制需要及早補上，不能只靠工程團隊的既有規範涵蓋全公司。
   建議後續：IT／法遵主管可用這份報告的具體數字（86%事故率、僅5%有明確權責分工）向處長提案，盤點公司內部AI工具核准流程的實際等候時間，評估是否需要建立更快速的「白名單申請」機制以降低員工私自使用未核准AI工具的誘因，同時確認企劃、客服等非工程部門若已開始使用agent類工具，是否已有對應的權責與稽核規範。
   來源：Help Net Security（https://www.helpnetsecurity.com/2026/09/15/onetrust-enterprise-ai-governance-trends-report/）；GlobeNewswire（https://www.globenewswire.com/news-release/2026/09/14/3361166/0/en/onetrust-research-86-of-organizations-experienced-ai-related-incidents-yet-few-slowed-deployment.html）

   建議後續：工程主管確認是否有腳本或內部工具明確指定呼叫GPT-5.5，若有應於10/14前排定改用GPT-5.6 Sol或GPT-6 Astra並驗證輸出品質；同時可請1名工程師留意Codex CLI外掛系統與Claude Code外掛市集互通的後續發展，評估是否能降低跨工具維護自製外掛的重複成本。

4. **主推工具動態／資安｜開發環境廠商Coder將Claude Code接進「Agent Relay」自架執行環境，鎖定金融等高度受監管產業**
   新聞內容：開發者工作區平台Coder於9/15宣布，旗下「Agent Relay」（一套讓雲端coding agent可在企業自有基礎設施上執行的自架環境，9/4先以SpaceXAI為首發夥伴推出）現已正式支援Claude Code。整合後，Claude Code的agent可在Coder工作區內執行，程式碼、憑證與所有agent觸碰到的資料都留在客戶自己控管的機器上（網路存取受管控、執行環境沙盒化、且全程可稽核），而Anthropic仍負責帳務與代理執行迴圈本身；官方說明每次agent執行都會產生對應該次session與使用者的完整稽核紀錄，企業並可額外設定程序層級的網路政策、記錄agent發出的每一筆對外請求。Coder官方表示，過去金融服務等高度受監管產業因法規要求「不得讓自主agent存取放在組織控管範圍外的原始碼、憑證與內部服務」，導入進度因此受限，這次整合正是為解決此一部署障礙而設計。
   為什麼對我們有意義：這與9/15已報導的Cursor Cloud Agents開放自架執行環境（AWS Lambda MicroVMs等）屬於同一波「把agent執行環境的控制權收回企業自己手上」趨勢，但這次是直接針對我們主推工具Claude Code的自架方案，多了一個選項；若公司未來考慮讓Claude Code處理更敏感的內部系統（如玩家資料庫、金流後台）自動化任務，這類「執行環境留在自己VPC內、每次操作皆可稽核」的架構，能降低資安團隊對「程式碼與資料離開公司網路邊界」的疑慮，也提供了與Cursor自架方案並列比較的具體參考對象。
   建議後續：資安與工程主管可共同索取Coder Agent Relay的技術文件與試用資訊，比較其與Cursor Cloud Agents自架方案在稽核紀錄完整度、網路政策設定彈性上的差異，若公司規劃讓Claude Code存取更敏感的正式環境系統，可將兩者一併納入「自架agent執行環境」的選型清單。
   來源：Coder官方部落格（https://coder.com/blog/agent-relay-claude-code-agentic-development）；GlobeNewswire（https://www.globenewswire.com/news-release/2026/09/15/3362210/0/en/coder-brings-claude-code-to-agent-relay-unlocking-agentic-development-for-the-world-s-most-regulated-enterprises.html）

   建議後續：工程主管待9/30 Hive Axyl正式上線後，可申請一份產品簡報或試用資源，評估其自然語言生成的後端程式碼在正確性與客製彈性上是否足以用於實際專案的原型驗證階段；若公司評估過Com2uS Hive或同類GBaaS服務，可將Hive Axyl的AI輔助功能一併納入下一輪後端服務供應商比較清單。

   新聞內容：開源專案「OmniRoute」（MIT授權，由diegosouzapw維護，逾550名貢獻者）是一套免費的AI閘道（AI gateway），讓Claude Code、Codex、Cursor、OpenCode、Cline、GitHub Copilot等主流coding agent都能透過單一端點，串接352家以上AI供應商（其中150多家提供免費額度）、超過1,200個模型（含Kimi、Claude、GPT、Gemini、GLM、DeepSeek、MiniMax等），並具備「配額感知自動容錯移轉（quota-aware auto-fallback）」機制，在某供應商額度用盡或逾時時自動切換備援來源；其「RTK+Caveman」堆疊式壓縮技術宣稱可為符合條件的請求省下15%至95%的token用量。專案近期釋出v3.8.49版本，星數已從今年稍早的約9,300顆大幅成長至突破6.1萬顆，官方宣稱聚合各供應商免費額度後，每月可提供約16億個免費token。

   建議後續：工程主管可指派1名工程師在非正式環境試裝OmniRoute，針對現有Claude Code或Codex CLI的高用量批次任務測試其token壓縮與自動容錯效果，並請資安人員一併確認請求轉發過程是否符合公司資料處理規範，再評估是否小範圍導入以緩解週用量上限壓力。
