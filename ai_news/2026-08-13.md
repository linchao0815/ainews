1. **主推工具動態｜Claude Code v2.1.229、v2.1.231 接連發布：新增自架執行器hook支援與Remote Control續接，並修復MCP OAuth登入Slack失敗問題**
   新聞內容：Anthropic於8月12日發布Claude Code v2.1.229，本次更新新增「自架執行器（self-hosted runner）」的hook支援（讓自架環境的行為與官方代管環境一致）、正式文件化`claude remote-control --continue`指令供使用者續接最近一次的Remote Control連線session、為gateway串流回應新增SSE keepalive訊號（避免長時間思考時被Vertex/Bedrock端閒置逾時斷線），並修復逾30項錯誤（含長回應串流中途消失、視窗過窄時當機、Windows長路徑當機等）。緊接著8月13日發布v2.1.231，修復一項會導致MCP OAuth登入失敗的問題——凡是採用「預先註冊OAuth用戶端」機制的MCP伺服器（例如Slack）先前會因redirect URI不匹配而無法登入，現已修復。
   為什麼對我們有意義：若我們工程團隊使用Claude Code的自架環境（self-hosted runner）跑agent任務，先前hook行為與官方代管環境不一致的問題已被修復，有助於統一內部SOP；若有人透過MCP協定串接Slack做通知或工作流整合，先前版本會直接卡在OAuth登入失敗，這次修復解除了這個實際會擋住工作流程的障礙；SSE keepalive的改善也對透過Vertex/Bedrock跑Claude Code的團隊，減少長任務中途斷線的困擾。
   建議後續：建議工程主管請團隊將Claude Code更新至v2.1.231以上版本，尤其是已串接Slack MCP或使用自架執行器的同仁應優先更新並驗證登入與hook行為是否恢復正常。
   來源：GitHub（https://github.com/anthropics/claude-code/releases）；Claude Code Changelog on X（https://x.com/ClaudeCodeLog/status/2087823250680148125）

2. **平台治理｜Cursor取得AIUC-1認證，成為首批通過coding agent專屬資安風險評測的AI編碼工具**
   新聞內容：Cursor於8月12至13日在官方部落格宣布取得「AIUC-1」認證，這是由Artificial Intelligence Underwriting Company聯合資安、風險與法律專家制定的AI agent安全標準，被業界稱為「AI agent版的SOC 2」，專門針對提示詞注入（prompt injection）、未經授權的自主行為、多步驟工具呼叫、資料外洩等一般傳統合規框架涵蓋不到的agent特有風險進行評測。官方表示Cursor的agent通過了橫跨12大類別、數千項技術評測，其中包含今年第三季才公開發布、專門針對「coding agent風險」的新版要求。
   為什麼對我們有意義：對「程式」與IT資安團隊而言，這是市場上第一批針對「coding agent」本身（而非通用AI聊天機器人）的第三方安全認證，若公司使用Cursor做內部程式開發，這份認證可作為向資安/法務單位證明「所選用的AI編碼工具已通過獨立第三方風險評測」的具體依據，減少內部安全稽核時需要自行從零評估agent風險的工作量；同時這也是評估其他家coding agent（Claude Code、Codex、Antigravity）時可比照要求提供同等認證的參考基準。
   建議後續：建議IT資安主管將AIUC-1認證資訊納入下一輪AI coding工具供應商安全評估表，並詢問Claude Code、Codex等其他主推工具是否有規劃取得同類認證，作為長期供應商風險比較的依據。
   來源：Cursor官方部落格（https://cursor.com/blog）；AIUC-1官方說明（https://www.aiuc-1.com/aiuc-1-certification）

3. **主推工具動態／資安｜Google Antigravity CLI本月連環更新：新增企業級SSO聯合登入、修補.git目錄可被寫入的沙盒疏漏**
   新聞內容：Google Antigravity CLI在8月接連發布v1.1.10（8/3）、v1.1.11（8/7）、v1.1.12（8/11）三個版本：v1.1.10新增「Workforce Identity Federation」聯合登入，讓透過外部身分供應商做SSO的企業可直接串接登入，同時收緊終端機沙盒權限，將agent對Git repo的`.git`目錄存取從「可寫入」改為「唯讀」，避免agent在沙盒內意外或被誘導改寫版本控制的底層資料；v1.1.11新增Vim編輯模式；v1.1.12則新增artifact檢視器的標題大綱導覽、為唯讀指令新增JSON/stream-json機器可讀輸出格式，並修復設定檔案損毀與URL工具連線洩漏等問題。此波更新內容與8月12日已報導的Antigravity CLI 2.7.1版「圖片並排比對」功能屬於不同批次的更新項目。
   為什麼對我們有意義：對「程式」與資安團隊而言，`.git`目錄從可寫入改為唯讀是實質的沙盒強化——先前若agent在沙盒中執行的操作出錯或被惡意提示誘導，理論上有機會直接竄改版本控制紀錄，這次修補後降低了此類風險；而Workforce Identity Federation聯合登入功能，則讓已有企業SSO系統的IT團隊能更順暢地將Antigravity CLI納入統一身分管理，減少員工另外管理一組獨立帳密的資安死角。
   建議後續：建議正在評估或已導入Antigravity CLI的工程團隊更新至v1.1.12以上版本，並請IT資安確認是否要串接公司現有SSO系統的Workforce Identity Federation，以統一納入帳號權限管理。
   來源：GitHub（https://github.com/google-antigravity/antigravity-cli/releases）

4. **GitHub趨勢｜開源「agency-agents」AI人格化角色包衝上13.9萬星，涵蓋工程、產品、行銷、客服等多職能，可一鍵安裝進Claude Code/Cursor/Codex**
   新聞內容：開源專案msitarzewski/agency-agents源自一則Reddit討論串，如今已成長為收錄超過230名「人格化」AI專家角色的合輯，涵蓋前端工程、後端架構、產品成長駭客、UX研究員、社群經營（含Reddit社群專員）、客服應答等跨職能領域，每個角色都附帶具體工作流程與可交付成果範本，而非單純的通用提示詞。截至8月中，該專案已累積約13.9萬顆星，並推出獨立的桌面應用程式（支援macOS／Linux／Windows），能一鍵瀏覽、安裝並自動更新這些角色到Claude Code、Cursor、Codex、Gemini CLI、OpenCode等多款AI coding工具中。
   為什麼對我們有意義：對「企劃室」與「運營／客服」團隊而言，這套角色包最大的價值在於它把「產品經理」「客服應答」「社群經營」等非工程職能的AI agent角色也標準化、模組化了，等於企劃或客服同仁不需要自己從零設計prompt，就能直接調用已被大量社群驗證過的角色設定，套用在企劃提案初稿、玩家社群留言草擬回覆、活動文案發想等場景；對「程式」團隊而言，也能快速調用架構師、程式碼審查等角色，補強現有Claude Code/Cursor的技能庫。
   建議後續：建議企劃室與客服主管各指派1名同仁試裝agency-agents桌面應用程式，挑選1-2個貼近日常工作的角色（如產品成長駭客、客服應答）在既有Claude Code/Cursor環境中試用一週，評估是否能縮短提案草稿或客服回覆範本的產出時間。
   來源：GitHub（https://github.com/msitarzewski/agency-agents）；AI fan on X（https://x.com/aias_0/status/2046045416035422632）

5. **GitHub趨勢｜「Graphify」+「code-review-graph」讓AI coding agent不必重複讀檔案，Graphify衝破10.5萬星、Y Combinator新創出品**
   新聞內容：開源專案Graphify（Apache 2.0授權）能將整個程式碼庫、文件、SQL schema、設定檔甚至PDF，轉換成一份可查詢的知識圖譜，讓Claude Code、Cursor、Codex等AI coding agent不必每次都重新逐檔案掃描專案就能理解程式架構；其做法是以本機的AST（抽象語法樹）靜態解析、不呼叫LLM，並透過git post-commit hook只針對變更的檔案在5秒內增量更新。該專案由印度首位以個人開發者身分入選Y Combinator S26梯的創辦人打造，短短數週內衝上超過10.5萬顆星；與其功能類似、可搭配使用的「code-review-graph」則是以SQLite儲存的AST圖譜，提供約25個MCP工具（可篩選為常用8個），支援語意搜尋與「異動影響範圍（blast radius）」分析。
   為什麼對我們有意義：對「程式」團隊而言，若目前使用Claude Code或Cursor處理較大型或年資較久的程式碼庫，agent每次啟動都要重新探索專案結構會消耗大量token與時間，Graphify這類「一次建圖、增量更新」的知識圖譜工具，有機會顯著縮短agent理解專案的時間、降低API token消耗，且完全在本機執行、不上傳程式碼到雲端，資安疑慮相對較低，特別適合套用在維護中的大型正式專案。
   建議後續：建議工程主管指派1名工程師在一個中大型、程式碼量較大的內部專案上試裝Graphify（或搭配code-review-graph），實測建圖後Claude Code/Cursor的回應速度與token消耗變化，評估是否值得推廣為團隊標準配置。
   來源：GitHub（https://github.com/Graphify-Labs/graphify；https://github.com/tirth8205/code-review-graph）；Axel Bitblaze on X（https://x.com/Axel_bitblaze69/status/2075713327100281317）

6. **成本情報｜Google發布Gemini 3.6 Flash與3.5 Flash-Lite，鎖定高流量低成本自動化任務，輸出定價較前代降17%**
   新聞內容：Google於7月21日發布Gemini 3.6 Flash與Gemini 3.5 Flash-Lite兩款模型，並於日前隨Antigravity等平台更新同步擴大供貨曝光。Gemini 3.6 Flash延續100萬token上下文窗口、知識截止日推進至2026年3月，定價為每百萬輸入token 1.5美元、輸出7.5美元，較前代3.5 Flash的輸出定價（每百萬9美元）降低約17%，且在程式撰寫、長文本與電腦操作類基準測試上表現更佳；3.5 Flash-Lite則主打高流量、低延遲的自動化任務，定價低至每百萬輸入0.3美元、輸出2.5美元，兩者上市首日即同步登陸Google AI Studio、Gemini API、Android Studio、Antigravity與Vertex AI／Gemini Enterprise。
   為什麼對我們有意義：對「程式」與IT成本控管而言，若公司有大量重複性、非核心的高頻呼叫任務（例如玩家回饋初步分類、批次資料格式轉換、內部工具的簡單問答），3.5 Flash-Lite這種每百萬輸入僅0.3美元的價位，比目前多數團隊慣用的Claude Sonnet系列便宜非常多，是即將於9月起面對Sonnet 5漲價50%的情境下，值得優先評估轉移的低敏感度任務候選模型；3.6 Flash則可作為中階任務（如程式碼審查輔助、長文件摘要）的高性價比替代選項。
   建議後續：建議IT成本負責人與程式主管，挑選1-2項目前用Claude Sonnet系列處理的低敏感度、高流量任務，試接Gemini 3.5 Flash-Lite或3.6 Flash進行AB測試，比較輸出品質與費用差異，作為9月Sonnet漲價後的成本分流方案。
   來源：Google AI for Developers Release Notes（https://ai.google.dev/gemini-api/docs/changelog）；9to5Google（https://9to5google.com/2026/07/21/gemini-3-6-flash-launch/）

7. **產業應用（程式／QA）｜Square Enix攜手Google Gemini打造AI自動QA測試平台，目標2027年底前讓AI處理70%測試除錯工作**
   新聞內容：Square Enix AI暨引擎開發部門總經理荒巻威（Takeshi Aramaki）於7月30至31日的Google Cloud Next Tokyo '26活動上，公開該公司利用Google Gemini打造的自動化QA測試平台細節：此AI系統能分析遊戲畫面、理解場景中的遊戲狀態，並據此自動操作controller進行實機測試，整個專案背後並有日本經濟產業省（METI）的資金支持。Square Enix同時與東京大學松尾・岩澤研究室展開聯合研究，設定目標是在2027年底前，讓AI自動完成公司內部高達70%的QA測試與除錯（debugging）工作，官方表示此舉是因應近年開發人力工作量持續攀升所做的因應對策。
   為什麼對我們有意義：這是同業大型遊戲公司首次公開「用AI實際操作controller玩遊戲來做QA」且設下具體時間表與比例目標（2027年底70%）的案例，對我們「程式」與QA團隊而言，具體展示了生成式AI從「輔助寫測試腳本」進一步走向「AI直接操作遊戲進行實機測試」的可行路徑，值得作為評估內部QA自動化投資規模與時程規劃時的同業對照指標；同時也提醒QA人力配置需要提前規劃「從人工測試轉為監督/複核AI測試結果」的角色轉型。
   建議後續：建議QA主管與工程主管共同追蹤Square Enix或東京大學研究團隊是否會公開更多技術細節或合作管道，並評估是否可先以小規模、非核心關卡的自動化回歸測試為起點，試驗「AI操作controller做QA」的可行性與成本效益。
   來源：PC Gamer（https://www.pcgamer.com/gaming-industry/square-enix-aims-to-have-ai-doing-70-percent-of-its-qa-work-by-the-end-of-2027-which-seems-like-itd-be-hard-to-achieve-without-laying-off-most-of-your-qa-workers/）；Game Developer（https://www.gamedeveloper.com/business/square-enix-wants-to-use-gen-ai-to-automate-70-percent-of-qa-and-debugging-by-late-2027）
