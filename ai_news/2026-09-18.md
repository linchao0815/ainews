1. **主推工具動態（頻道分享）｜Claude Code Projects全面重做：從資料夾變成「一場對話＋多條並行雲端session」**
   新聞內容：Anthropic於9/17發布部落格文章「Projects redesigned: from folder to conversation」，宣布重新設計Claude Code的Projects功能。新版把Projects從單純的檔案資料夾，改造成一個持續進行的對話：使用者在Claude Code描述目標後，Claude會扮演協調者角色，把工作拆解、同時開啟多條雲端session（各自對應獨立的git branch或repo複本）平行執行，過程中自動開PR、跑測試，即使使用者離線也會持續進行；所有並行thread共用同一份「共享記憶」，會記得像是「發布延到週五」「為什麼拿掉匯出功能」「動billing服務前要先問誰」這類團隊脈絡，減少重複下指令的prompt工程負擔。目前beta僅開放給部分使用雲端session、且尚未有舊版projects的Claude Pro／Max用戶，未來一週內會擴大到更多Claude Code用戶，之後才輪到Team／Enterprise方案。
   為什麼對我們有意義：這代表Claude Code正式把「多agent協調」內建進主力工具的核心工作流，而非額外UI；未來若我們同時有多個功能分支要並行開發（例如活動系統、商城改版、bug修復同時進行），理論上可以讓一個Claude Code session同時協調、追蹤多條分支的進度並共享上下文，對程式團隊的並行開發效率與知識延續性是直接利多；但官方也提醒用量額度會更快被燒完，牽動我們Claude Enterprise方案的成本規劃，資安與IT也需留意多條雲端session同時存取repo的權限控管。
   建議後續：工程主管在beta開放到我們帳號後，先挑一個可拆成3-5個獨立子任務的中小型功能試跑Projects協調模式；企劃室與IT同步追蹤用量消耗速度，評估是否需要調整Enterprise方案額度或啟用先前討論過的Smart Reports用量分析工具。
   來源：Claude by Anthropic（https://claude.com/blog/projects-redesigned）；人蔘 Try Catch on Threads（https://www.threads.com/@ginsengtrycatch/post/DdZ91Yon6bv）

2. **主推工具動態／工具能力（程式，頻道分享）｜GitHub把Copilot執行引擎全面重寫成Rust，AI agent主刀完成逾80萬行程式碼**
   新聞內容：GitHub官方部落格證實，已把支撐Copilot CLI、App與SDK的執行引擎（runtime），從原本的TypeScript／Node.js／Google V8架構，全面改寫為Rust，總計超過80萬行production等級程式碼，耗時約14.5週（略超過3個月）完成，透過128個獨立PR分批合併進主幹、隨開發過程逐步上線，而非一次性大改版切換。這次重寫絕大部分程式碼由AI agent（GitHub Copilot自身）撰寫，僅由一名工程師主導、其餘團隊成員同步繼續開發新功能；官方指出原本的TypeScript架構在SDK使用情境下有明顯開銷問題，重寫後執行效能有數量級的提升。
   為什麼對我們有意義：這是目前最大規模、被官方正式證實「AI agent主導」的正式生產環境重寫案例，直接示範coding agent已經可以承接「大型架構重構／語言遷移」這類我們長期不敢碰的高風險技術債任務；對程式團隊而言，若公司內部有老舊、效能瓶頸明顯的服務，這個案例證明用agent做漸進式、可分批上線的重寫是可行策略，不必一次性大改版承擔風險，也能作為評估agent開發能力上限的重要參考指標。
   建議後續：工程主管挑選1-2個技術債嚴重但範疇明確的內部服務，比照「分批PR、邊重寫邊上線」的模式，用Claude Code小規模試點一次語言或框架遷移，評估可行性、產出品質與所需的人工監督成本。
   來源：The GitHub Blog（https://github.blog/ai-and-ml/generative-ai/migrating-the-github-copilot-runtime-to-rust-using-copilot/）；Will 保哥的技術交流中心 Facebook貼文（https://www.facebook.com/100064322940906/posts/1540317314789019/）

3. **成本情報｜LLM API定價開打「快取戰」：Claude Fable 5.1快取讀取價砍75%，Sonnet 5維持$2/$10不調漲**
   新聞內容：根據9月的定價分析報導，Anthropic已於8/11把Claude Sonnet 5的費率（每百萬token輸入/輸出$2/$10）永久定案，原訂9/1調漲至$3/$15的計畫確定不會執行；同時9/1上線的新模型Fable 5.1，基礎價格雖達$10/$50，但把「快取讀取」（cache read）價格砍75%至每百萬token僅$0.25，被業界稱為「快取讀取戰爭」的開端。另以9/15為基準，在27家供應商、156款付費模型中，最便宜的是Qwen3.7 Flash，每百萬input/output token僅$0.03/$0.13；報導也指出除xAI外，各家供應商目前都已提供批次處理（batch）五折優惠。
   為什麼對我們有意義：我們內部大量使用Claude API處理重複性高的分析、內容生成任務（例如本情報摘要、企劃文案初稿），這類任務通常有大量重複的系統提示或參考文件可以命中快取；Fable 5.1快取讀取砍75%，若我們的使用情境常需要長系統提示或大型文件重複讀取，改用Fable 5.1並善用快取，實際總成本可能比表面上$10/$50的基礎價更划算，值得重新試算目前各團隊的token使用結構，避免只看牌價就排除新模型。
   建議後續：負責AI成本控管的同事抽查近一個月Claude API呼叫紀錄中「重複前綴／長系統提示」的比例，試算若改用Fable 5.1並最佳化快取命中率，總支出是否下降；若有明顯節省空間，向處長提案調整預設模型與prompt快取策略。
   來源：dreaming.press（https://dreaming.press/posts/llm-api-pricing-september-2026-ceiling-cache-reads-promo-cliff.html）

5. **工具能力／平台治理（資安／程式，頻道分享）｜開源Agent框架Hermes擴充插件生態：記憶稽核、Snyk資安掃描、時間點回溯搜尋三箭齊發**
   新聞內容：NousResearch旗下開源agent框架「Hermes Agent」近期一口氣推出三款官方插件：①Memory Wiki，把agent的長期記憶整理成主題、日誌與近期狀態頁面，讓使用者能直接稽核（audit）persistent memory裡到底存了什麼；②hermes-plugin-snyk，透過Snyk官方MCP server把code、dependency、container、IaC、SBOM掃描直接接入agent工作流，plugin內建snyk-security-scan技能自動處理驗證、掃描、修復的完整流程，目前pin住的版本為snyk@1.1306.0（2026/7/9發布）；③BackSearch，讓agent搜尋時能指定「as_of」時間點，只取得該時間點以前的資料，降低用未來資訊污染歷史研究或回測（backtest）結果的風險。三款皆為獨立GitHub repo，可透過`hermes plugins install`個別安裝啟用。
   為什麼對我們有意義：目前我們評估或使用agent工具時，最大顧慮就是「agent到底存了什麼記憶」以及「agent操作能不能先做資安掃描再放行」，Hermes這套插件把這兩個痛點都做成了可直接安裝的標準化模組；即使我們主力用的是Claude Code而非Hermes，這個架構也提供了「記憶可稽核＋內建資安掃描」的產品設計參考範本，資安團隊可拿來對照評估我們自己的agent工作流是否有對應的防護缺口。
   建議後續：資安負責人研究hermes-plugin-snyk的MCP整合方式，評估是否能用類似手法把既有的SAST/SCA掃描工具，透過MCP接進我們Claude Code的工作流程，讓程式碼在agent產出後自動先過一輪資安掃描。
   來源：GitHub - NousResearch/hermes-plugin-snyk（https://github.com/NousResearch/hermes-plugin-snyk）；GitHub - NousResearch/hermes-memory-wiki（https://github.com/NousResearch/hermes-memory-wiki）；GitHub - NousResearch/hermes-plugin-backsearch（https://github.com/NousResearch/hermes-plugin-backsearch）；Kevin Wang on Threads（https://www.threads.com/@kevinbuilds_ai/post/DdZ-YWwEmXQ）

   新聞內容：開源專案「ai-data-extractor」是一款免費工具，能把儲存在本機的AI coding agent對話紀錄——包括Claude Code、Cursor、Windsurf、Aider、Cline/Roo Code等——一次性擷取出來，統一轉換成單一標準化的JSONL格式，並保留完整的檔案路徑、程式碼diff、工具呼叫紀錄等中繼資料，方便使用者拿去備份、做個人化用量分析或做為微調（fine-tuning）訓練資料。該工具解決的痛點是：目前各家agent工具都把對話紀錄各自存在不同格式的本機資料夾裡，換工具、重灌系統或app清除資料時容易整批遺失。

   建議後續：IT或企劃室安排一次性試用，針對幾位資深工程師的Claude Code/Cursor對話紀錄做匯出測試，評估資料量與品質，若可行則納入內部知識管理流程定期備份。
