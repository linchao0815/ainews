1. **主推工具動態｜Claude Code v2.1.248／v2.1.250發布：新增`--restricted`嚴格沙箱模式與per-agent Prompt Cache TTL設定**
   新聞內容：Anthropic於8月27日發布Claude Code v2.1.248，新增`--restricted`旗標（或環境變數`CLAUDE_CODE_RESTRICTED=1`），啟用後會移除所有可執行指令或程式碼的內建工具與WebFetch（除非在`--tools`中另外指名允許），檔案工具也會被限制在工作目錄範圍內、拒絕`bypassPermissions`模式，並且完全忽略使用者、專案與local層級的設定檔——等於提供一個「最小權限」的沙箱執行模式。同版本也在agent frontmatter新增`experimental.cacheTtl`（可設"5m"或"1h"），讓每個子代理（subagent）可個別指定prompt cache存留時間，不受全域subagent TTL設定綁定。緊接著8月28日發布的v2.1.250則主要為錯誤修復與穩定性改善，包含remote-control旗標處理、啟動警告顯示與worktree session管理等問題。
   為什麼對我們有意義：對工程與資安團隊而言，`--restricted`模式提供了一個可直接套用在「不完全信任的任務」上的官方沙箱選項——例如讓agent處理外部貢獻者的PR、執行自動化程式碼審查、或在CI環境跑不受信任的腳本時，可以強制阻擋agent執行任意指令或存取工作目錄外的檔案，降低prompt injection或誤操作造成的破壞範圍，且不必自行搭建額外的沙箱基礎設施；per-agent cache TTL設定則能讓工程主管針對不同用途的子代理（如短期一次性任務vs.長時間對話）分別調校快取策略，優化API呼叫成本。
   建議後續：建議工程主管指派1名工程師評估在CI流程或處理外部PR的agent任務中導入`--restricted`模式，作為降低agent誤操作風險的預設安全基準；同時請負責Claude Code用量成本的窗口研究`experimental.cacheTtl`設定，針對高頻率呼叫的子代理任務調整快取時間以降低token成本。

2. **平台治理／資安｜Anthropic「Inference Hooks」為Claude Enterprise加裝即時DLP攔截閘門，Palo Alto Networks Prisma AIRS率先原生整合**
   新聞內容：Anthropic於8月5日推出Claude Enterprise新功能「Inference Hooks」（目前為beta），運作方式是每一次prompt在真正送進Claude模型推論之前，會先被送到企業自己指定、自行維運的AI資安伺服器進行檢查，該伺服器回傳「允許」或「拒絕」的判決，Claude才會決定是否繼續處理——若判定拒絕，該prompt完全不會進入模型；目前判決僅支援二元的允許/拒絕，尚不支援自動改寫或遮蔽敏感內容後再放行。此機制以webhook協定串接，官方公開文件已列出Netskope、Palo Alto Networks、Proofpoint、Zscaler等資安廠商可作為對接端點，單一組織層級設定即可同時涵蓋claude.ai聊天介面、Claude Code與Claude Cowork三種介面，但目前僅涵蓋Claude Enterprise，API直接呼叫與跑在AWS Bedrock／Google Cloud上的Claude不在此範圍內。Palo Alto Networks已於8月宣布其Prisma AIRS平台原生對接此機制，讓企業可直接沿用既有的Enterprise DLP規則（如精確資料比對、機密分類器、原始碼憑證偵測）套用到所有Claude環境，不必為Claude另外建置一套規則。
   為什麼對我們有意義：對資安／IT團隊而言，這項功能直接補上了先前多次報導提及的「AI agent推論流量繞過傳統DLP規則」缺口——若公司員工透過Claude Cowork或Claude Code處理玩家個資、未公開財報或原始碼等機敏內容，過去傳統DLP工具（設計給email附件、隨身碟）看不到這類流量，Inference Hooks讓資安團隊能在prompt進入模型「之前」就攔截機敏資料外洩，且能沿用既有DLP規則不必重造一套；但因目前只做允許/拒絕、不能自動遮蔽改寫，實際導入時可能會有「合法但誤判」的prompt被整批擋下，需要搭配明確的例外處理流程。
   建議後續：建議資安主管將Inference Hooks列為Claude Enterprise帳戶的優先啟用項目（目前仍為beta，需評估穩定性），若公司已採用Palo Alto Networks、Netskope、Proofpoint或Zscaler其中之一作為DLP方案，可直接洽詢是否已支援對接；同時IT窗口應規劃「prompt遭拒絕」後的員工申訴或例外放行流程，避免正常工作流程被誤擋而影響生產力。

3. **平台治理／主推工具動態｜Cursor取得AIUC-1 AI Agent安全標準認證，經Schellman獨立稽核**
   新聞內容：Cursor於8月13日在官方部落格宣布已取得「AIUC-1」認證——這是一套結合組織控管稽核與產品對抗性測試（adversarial testing）的AI agent安全、安全性與可靠性新標準，由逾百位財星500大企業CISO與風險主管參與制定，並取得MITRE、Cloud Security Alliance與史丹佛大學研究人員的技術貢獻。Cursor的agent經過涵蓋12大類別、數千項技術評測，並通過針對「coding agent」風險新增的AIUC-1特定要求（涵蓋機密資訊保護、安全程式碼產生、MCP安全性、agent身分與權限管理等面向），該套coding agent專屬要求已於2026年第三季正式公開發布。此次稽核由Schellman執行——該機構同時是全球第一家取得ANAB認證的ISO 42001認證機構、也是首家獲授權執行AIUC-1稽核的機構；Cursor目前另已持有AIUC-1、ISO/IEC 27001:2022、ISO/IEC 42001:2023三項認證，以及SOC 2 Type II證明。
   為什麼對我們有意義：對資安與工程主管而言，這項認證提供了一個由第三方獨立稽核、且專門針對coding agent風險（如機密外洩、不安全程式碼產生、MCP權限濫用）設計的可信賴度指標，若公司已將Cursor列為主推工具之一，可用此認證作為向資安委員會或處長報告時的具體佐證，減少「開放式agent架構是否安全」的疑慮；相較於本系列先前多次報導的開源agent工具（如OmniRoute、Ruflo）因權限過寬爆出漏洞的案例，AIUC-1這類正式安全標準的出現，也代表企業評估coding agent供應商時，未來可將「是否通過AIUC-1」納入採購與資安評估的具體檢核項目。
   建議後續：建議資安主管將AIUC-1認證的12大評測類別（機密保護、MCP安全性、agent權限管理等）取得詳細報告或白皮書，比對公司內部對Cursor的實際使用情境（如是否串接內部程式碼庫、是否啟用MCP工具），確認現有使用方式是否已在認證涵蓋範圍內；同時可將AIUC-1列為日後評估其他AI coding agent供應商（如是否要求Claude Code、Codex也取得同等認證）的採購檢核標準之一。

   為什麼對我們有意義：對IT與財務主管而言，若公司工程或企劃團隊已在使用ChatGPT Work／Codex，Admin外掛提供了與本系列8/27已報導的Claude Enterprise Compliance／Admin API相近的「對話式管理」能力，能降低過去需要窗口人員手動處理權限異動、支出審核的行政負擔，可作為與Claude陣營治理功能對照評估的具體項目；WebMCP則代表「網站主動暴露可控操作介面給AI agent」正成為業界另一種官方標準做法（相對於MCP由使用端驅動），若公司有自建的營運後台或玩家客服系統，未來可評估比照WebMCP規格開放特定功能給AI agent直接呼叫，比純瀏覽器自動化更安全、更可控。
   建議後續：建議有使用ChatGPT Work／Codex的部門，由IT窗口試用Admin外掛處理團隊成員異動與用量報表查詢，評估是否能取代現有手動流程；工程主管可同步指派人力研究WebMCP規格與`webmcp-kit`等開源實作範例，評估是否適合為公司內部無公開API的後台系統加裝可控的agent操作介面。
