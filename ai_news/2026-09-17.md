2. **主推工具動態／資安｜Claude Code連發v2.1.273、v2.1.274：修補權限檢查器安全漏洞、新增記憶體臨界警告**
   新聞內容：Anthropic於9/15發布Claude Code v2.1.273，共64項CLI變更，其中8項屬安全性修復，最關鍵的是兩項permission-checker（權限檢查器）漏洞：其一，過去若Bash指令內容複雜到權限檢查器無法完整解析，在`blockReadsOutsideWorkingDirectories`設定下會直接跳過確認提示、未經授權即執行；其二，在bypass模式下，可利用subshell（子殼層）語法隱藏一個危險的`rm`指令，使其逃過權限檢查直接執行刪除。此版本同時修復長時間session中過早觸發auto-compact（自動壓縮對話紀錄）的問題，並新增遠端控制session可分叉為背景本機session、MCP伺服器中途斷線即時通知等功能。接續於9/17發布的v2.1.274共108項變更，新增記憶體用量達臨界值時顯示明確警告並提示釋放記憶體或安全重啟的步驟，並新增`CLAUDE_CODE_MCP_STARTUP_WAIT_MS`環境變數可限制首次非互動輪次等待MCP伺服器連線的時間上限，同時修復session因「unexpected tool_use_id」400錯誤無限重試卡住、現受損對話紀錄可自動修復的問題。
   為什麼對我們有意義：兩項permission-checker安全修復直接補上工程團隊長期擔心的「agent在bypass或自動沙盒模式下執行看似安全、實際危險指令」漏洞——尤其「subshell藏rm指令」手法若未修補，等於讓惡意或誤植腳本能繞過既有防護直接刪除檔案，資安主管應優先確認公司內部是否已升級到修補版本；記憶體臨界警告與MCP啟動逾時設定，則能降低工程師在執行長任務或大量MCP工具串接時，因程式無預警當機或卡死而中斷工作、遺失進度的風險，對日常大量使用Claude Code處理長時間重構或批次任務的程式團隊有直接助益。
   建議後續：工程主管本週內確認團隊Claude Code版本已升級至v2.1.274，尤其若團隊有使用bypass模式或自動沙盒模式執行Bash指令的自動化流程，應優先升級以避開subshell隱藏rm指令的安全漏洞；同時可請1名工程師評估是否設定`CLAUDE_CODE_MCP_STARTUP_WAIT_MS`，為公司常用MCP伺服器連線時間設一個合理上限，避免長任務啟動卡住。
   來源：GitHub Release（https://github.com/anthropics/claude-code/releases/tag/v2.1.273）；Claude Code Changelog官方X發文（https://x.com/ClaudeCodeLog/status/2099961957352656925）；DevelopersIO（https://dev.classmethod.jp/en/articles/20260916-cc-updates-v2-1-273/）

3. **主推工具動態(輔)｜Google Antigravity CLI跳版至v1.2.5：新增子agent名冊自動注入、`/skills reload`免重啟更新技能**
   新聞內容：接續9/11正式對所有使用者開放、9/13發布v1.2.0新增背景常駐Remote Control服務，Google於9/17（今日）再發布Antigravity CLI v1.2.5。核心新增功能包括：新增`/skills reload`子指令，可非同步重新載入已偵測到的技能與斜線指令，不必重啟整個session或中斷使用者輸入；為自訂Markdown格式agent新增「自動子agent引導」機制——只要該agent的工具清單中包含`invoke_subagent`，系統會自動在其system prompt中附上目前可用的子agent名冊與使用說明，不必手動維護清單；`/model`指令新增輸入時的行內自動完成下拉選單，以及互動式`/model`選擇器內建即時模糊搜尋列，方便依名稱或ID快速篩選模型。此版本同時修復多項錯誤，包括OAuth權杖缺少必要授權範圍時的錯誤訊息不夠明確、跨模型切換至Gemini思考模型時因前幾輪由非Gemini模型產生而觸發`thought_signature`驗證錯誤，以及`/agents`面板「建立新agent」區塊顯示錯誤的全域設定目錄路徑等問題。
   為什麼對我們有意義：對已導入Antigravity CLI作為Claude Code之外備援或比較工具的工程團隊而言，`/skills reload`免重啟更新技能的功能，能降低團隊頻繁調整自製技能（如美術規範檢查、企劃文件範本）時反覆重啟session的操作成本；「自動子agent引導」機制則簡化多自訂agent協作時的維護工作，避免工程師每次新增或修改子agent後都要手動同步更新其他agent的呼叫說明，對正在嘗試建立跨agent分工流程（如企劃、程式、美術各自對應不同agent角色）的團隊有直接助益。
   建議後續：已使用或評估Antigravity CLI的工程團隊可指派1名工程師升級至v1.2.5，實測`/skills reload`與自動子agent引導功能是否能簡化目前手動維護多個自訂agent設定的流程，評估後決定是否值得推廣到團隊日常使用規範。
   來源：GitHub Release（https://github.com/google-antigravity/antigravity-cli/releases/tag/1.2.5）；GitHub Changelog（https://github.com/google-antigravity/antigravity-cli/blob/main/CHANGELOG.md）

6. **平台治理／資安｜西班牙資料保護局(AEPD)登記首宗「AI agent自主發動」的資料外洩通報案**
   新聞內容：西班牙資料保護局（AEPD）於9/14收到一起資料外洩通報，通報方指出攻擊是由一個搭載已知大型語言模型的AI agent自主發動——該agent先掃描受害系統的一般檔案找出弱點、成功登入系統後，接著在系統內自主搜尋其他應用程式的安全漏洞，最終修改了個人資料並存取了發票等財務文件，整個攻擊鏈條由agent自行串接完成，過程未見人工直接介入的紀錄。多家資安媒體於9/16-17跟進報導，指出這是各國資料保護主管機關首度正式登記「由AI agent主導的資料外洩」案件，標誌著AI輔助攻擊從過去以深偽（deepfake）、自動化釣魚等「理論風險」轉變為具體可通報的真實案例；AEPD刻意未公開涉案的具體AI模型與供應商名稱，並聲明使用特定模型不代表該模型或其供應商基礎設施遭入侵，也不代表該技術是為惡意目的而設計。目前受害公司身分與案件後續調查結果尚未公開，AEPD也尚未完成事件查證。
   為什麼對我們有意義：這起事件與本頻道近期持續追蹤的PaperCut集群化攻擊（9/13已報導）、Emergence AI多agent資安研究（9/16已報導）屬同一系列風險光譜的最新進展，但這次的意義在於「從研究模擬與觀察到的攻擊行為，正式進入官方資料保護機關的法定通報紀錄」——代表未來若公司系統遭遇類似AI agent自主串接漏洞掃描、入侵、竊取資料的攻擊，很可能會被歸類為需要正式通報主管機關的資安事件，而非單純的傳統駭客攻擊處理流程；資安與法遵團隊應留意國內主管機關未來是否會參考此案例調整資安事件通報分類標準。
   建議後續：資安主管將此案例併入近期agent資安風險簡報，特別標註「官方機關已開始正式歸類AI agent主導攻擊」這項制度面新進展；法遵窗口確認公司現行資安事件通報SOP是否已涵蓋「攻擊媒介為AI agent」這一類情境的通報欄位與應變流程，若尚未涵蓋應提前規劃納入下一輪SOP更新。
