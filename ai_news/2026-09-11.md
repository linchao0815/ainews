1. **平台治理／資安｜MCP供應鏈攻擊「Deadbugz」現身：偽裝生產力工具，累計呼叫3次後才變臉竊取憑證**
   新聞內容：資安研究機構Pillar Security發布報告，揭露一起正在進行中的MCP（Model Context Protocol）伺服器供應鏈攻擊行動，命名為「Deadbugz」。攻擊者以GitHub帳號「zellkernel」為主要投放管道，於8/10晚間9:52至11:07短短74分鐘內，向多個不相關的AI／MCP／開發工具專案送出23個夾帶惡意MCP伺服器的Pull Request；該伺服器對外自稱「productivity-suite」，提供文字排版與摘要等看似無害的功能，但只要連接的客戶端（如coding agent）呼叫工具滿3次，伺服器就會悄悄置換回傳給agent的metadata指令，改為引導agent搜尋SSH金鑰、AWS憑證、shell歷史紀錄與Kubernetes設定檔，並要求agent對使用者隱瞞這些動作。研究人員審查時，23個PR中19個已被關閉、4個仍開啟，顯示攻擊仍在擴散中；業界同期彙整報告也指出9月另有3起新的MCP伺服器CVE被揭露。
   為什麼對我們有意義：這與9/8已報導的GitSpawn（利用Git設定觸發程式碼執行）屬於不同攻擊面但同等嚴重的風險——Deadbugz鎖定的是Claude Code、Cursor等工具普遍使用的MCP擴充生態系本身，且刻意設計「用滿3次才變臉」的延遲觸發機制，代表工程團隊即使在導入前先簡單試用測試過某個MCP伺服器，也可能因為測試次數不足而誤判為安全，等到正式導入大量呼叫後才觸發竊密行為，對程式與資安團隊而言是比先前已知漏洞更難靠人工審查抓到的風險型態。
   建議後續：資安主管將「MCP伺服器安裝前需完整執行5次以上工具呼叫並記錄回傳metadata是否有變化」納入內部審查SOP，並盤點目前公司內部Claude Code／Cursor環境中已安裝的第三方MCP伺服器來源，優先複查來路不明或近期才透過PR／論壇推薦安裝的項目。
   來源：Pillar Security官方部落格（https://www.pillar.security/blog/deadbugz-currently-active-mcp-supply-chain-campaign）；Adversa AI資安週報（https://adversa.ai/blog/top-mcp-security-resources-september-2026/）

2. **主推工具動態｜Claude Code v2.1.269發布：新增`claude plugin eval`技能測試框架與跨環境`/output-style`切換**
   新聞內容：Anthropic於9/11（今日）發布Claude Code v2.1.269。核心新功能是`claude plugin eval`指令，讓開發者可在外掛（plugin）的`evals/`資料夾中，為每個測試案例撰寫`prompt.md`與對應的`graders/`評分規則，支援6種評分類型——其中regex、tool_used、tool_order、file_exists四種完全依賴對話紀錄與磁碟檔案本地計算、不產生額外費用，另外llm（依撰寫的文字標準評分）與baseline（與參考答案比對）則會呼叫評審模型並計費；同時新增`/output-style [name]`指令，可在Remote Control、雲端與headless session間統一列出並切換輸出風格，另新增Bash指令變更檔案的diff顯示、OpenTelemetry儲存庫屬性欄位，並修復了中斷回應時prompt cache失效、多款終端機（kitty、st、rxvt-unicode、WezTerm）按鍵綁定異常等問題。
   為什麼對我們有意義：對已用Claude Code客製多組技能包（如美術規範檢查、企劃文件範本）的工程團隊而言，`claude plugin eval`等於官方提供了「技能包CI測試框架」——過去只能憑經驗判斷某個技能是否真的被正確觸發、是否真的達到預期效果，現在可以寫成可重複執行、可放進CI流程的自動化測試案例，直接降低技能包上線後才發現「其實沒被用到」或「效果不如預期」的品質風險。
   建議後續：工程主管指派1名工程師針對公司目前最常用的1-2個自製Claude Code技能包，試寫一組`evals/`測試案例（優先用不計費的regex/tool_used類型評分器），評估是否能將其納入既有CI流程作為技能包上線前的品質關卡。
   來源：GitHub Release（https://github.com/anthropics/claude-code/releases/tag/v2.1.269）；MarkTechPost（https://www.marktechpost.com/2026/09/11/anthropic-adds-plugin-evals-to-claude-code-6-grader-types-a-no-plugin-baseline-and-a-ci-gate-for-skills/）

3. **主推工具動態｜Cursor推出「Projects」測試版：Coordinator Agent可同時調度數千個子agent，重度用戶PR產出暴增6倍**
   新聞內容：Cursor於9/10發布「Projects」測試版功能，讓使用者不必為每個任務各自開一個對話，而是與一個常駐的「協調者（coordinator）」agent在單一持續對話串中互動；coordinator本身不寫程式碼，而是負責規劃工作、將任務拆分派給負責實作的子agent（可同時平行執行數千個），並在完成後將成果彙整回來讓使用者確認。Projects可設定提醒、排程任務、追蹤PR以修復CI問題、監看Slack上的錯誤回報等，且專案內所有agent共用記憶與產出的計畫、demo等檔案，會自動同步到裝置與雲端運算環境；Cursor官方數據顯示重度使用Projects的用戶合併的PR數量是過去的6倍，一般新用戶也提升30%。
   為什麼對我們有意義：這代表Cursor的agent能力已從「單一任務、單一對話」進化到「常駐協調者＋數千子agent並行」的專案級自動化模式，對程式團隊而言，若能用在例行性但耗時的工作（如追蹤多個repo的CI失敗、批次修復lint錯誤、監看特定Slack頻道的bug回報並自動建立修復PR），有機會大幅減少工程師手動巡查與重複開對話的時間成本；但coordinator可同時調度數千子agent的規模，也代表若無適當的權限與範圍控管，可能在短時間內對多個repo產生大量自動變更，工程主管需要謹慎設計其存取範圍與人工複核關卡。
   建議後續：工程主管指派1-2名資深工程師以測試版小規模試用Projects，先限定在單一非關鍵repo（如內部工具或文件庫）觀察coordinator的任務拆分品質與PR產出正確率，評估是否適合擴大到正式專案的CI修復或例行維護工作。
   來源：Cursor官方X貼文（https://x.com/cursor_ai/status/2098162488013455784）；AI Weekly（https://aiweekly.co/alerts/cursor-ships-projects-beta-with-delegating-coordinator-agent）；Cursor官方Changelog（https://cursor.com/changelog/projects）

4. **主推工具動態｜Google Antigravity CLI v1.2.0新增「Remote Control」背景服務，可跨登出／重開機持續在線**
   新聞內容：Google於9/10發布Antigravity CLI v1.2.0，新增`remote-control start`／`status`／`stop`三個子指令，可將CLI註冊為作業系統層級的背景服務，讓機器即使登出或重開機後仍可透過手機或瀏覽器連線存取，並支援以`--name`設定自訂機器標籤、`--session`將服務限定在目前登入階段；此功能延續Google稍早於8/21透過官方X帳號公告、原本僅限桌面版Antigravity 2.0使用的「Remote Control」能力，現已下放到CLI層級。同版本也修復了內容安全過濾器攔截時只顯示靜默失敗、暫存目錄檔案觸發不必要的檔案系統監控等問題，並改善整體延遲表現；隔日再發布的v1.2.1則進一步強化模型API暫時性錯誤的自動重試與MCP工具schema驗證。
   為什麼對我們有意義：對已導入Antigravity CLI的工程團隊而言，Remote Control下放到CLI意味著可以把常駐的自動化任務（如夜間批次重構、排程測試）留在公司內部伺服器背景執行，工程師不需保持電腦開機也能透過手機查看進度或處理需要人工確認的步驟，對需要長時間執行任務的場景（如大型重構、跨檔案除錯）能提升人力運用效率；但將CLI註冊為系統背景服務也代表其存取權限與存活時間拉長，資安團隊需要一併評估背景服務帳號的權限範圍是否比一般互動式session更需要限制。
   建議後續：已使用Antigravity CLI的工程團隊可指派1名工程師在測試機評估Remote Control背景服務功能，同時請資安人員確認該背景服務帳號的存取權限設定是否符合最小權限原則，再決定是否用於正式排程任務。
   來源：GitHub Changelog（https://github.com/google-antigravity/antigravity-cli/blob/main/CHANGELOG.md）；TestingCatalog於X轉發Google Antigravity官方公告（https://x.com/testingcatalog/status/2091154278526202052）

   新聞內容：DeepSeek於8/13發布開源、MIT授權的agent執行框架「DeepSeek Harness」（簡稱dsh），採「everything is a plugin」架構，模型介接、工具註冊、對話紀錄、agent執行迴圈等核心元件全部可替換式外掛化。此專案上線後star數暴增速度創下GitHub紀錄——上線約53小時內即衝破11.2萬星、逾1萬次fork，平均每小時新增超過2,100顆星，四天後更衝上13.5萬星、1.36萬次fork，超越先前OpenClaw保持的最快紀錄。由於是完全開源、可自行部署的agent框架而非封裝好的商用產品，開發者可自由替換其中的模型層，不受限於單一供應商。
   為什麼對我們有意義：對已在評估「用開源框架自建內部agent工具、降低對Claude Code／Cursor等商用訂閱依賴度」的工程團隊而言，DeepSeek Harness提供了一個經過大規模社群關注與貢獻驗證的現成基礎框架選項，其「everything is a plugin」設計理念也代表若公司想串接自有的內部系統（如玩家資料庫查詢、內部工單系統）作為agent工具，改動幅度可能比修改商用工具的外掛機制更有彈性；但完全自建也代表所有的資安沙盒、權限控管、穩定性維運都得自己承擔，不像Claude Code／Cursor有供應商既有的企業治理功能可用。
   建議後續：工程主管可指派1名工程師在非正式環境試裝DeepSeek Harness，評估其外掛架構是否適合用來包裝1-2個內部低風險的自動化工具（如日誌整理、批次腳本執行），並比較自建維運成本與現有商用訂閱費用的長期差異，作為「build vs. buy」agent基礎設施決策的參考資料點。
