1. **成本情報｜Anthropic將Claude Sonnet 5優惠價「永久保留」，取消9/1起的漲價計畫**
   新聞內容：Anthropic於8月11日宣布，Claude Sonnet 5今年6月上市時的優惠價（每百萬輸入token 2美元／輸出10美元）將永久維持，原訂9月1日起漲至3美元／15美元的標準價格計畫正式取消。此消息由Anthropic官方帳號於X（Twitter）發布確認，多家報導（Medium、EnterpriseDNA）均引用官方原文佐證。目前Claude Sonnet 5仍是公司內部使用量最大的模型定位（介於Opus與Haiku之間的主力機型），這次價格政策逆轉直接影響往後所有以token計費的內部用量預算。
   為什麼對我們有意義：若企劃室或工程團隊先前已按9月起漲價3成的假設編列下半年AI工具預算，現在可以直接取消該項調整，維持原有成本估算；對大量呼叫Claude API做內容生成、程式輔助的團隊（如企劃室文案生成、工程部Code Review自動化）而言，這代表沒有突發的成本壓力，可以更放心規劃長期、高用量的自動化流程。
   建議後續：財務／IT窗口可將原先為9月漲價保留的預算緩衝金額重新分配，企劃室可評估是否擴大Sonnet 5的內部應用範圍（如批量生成企劃文件、玩法草稿）。
   來源：Claude on X（https://x.com/claudeai/status/2086891169217122586）；EnterpriseDNA（https://enterprisedna.co/resources/news/anthropic-claude-sonnet-5-pricing-permanent-reversal-august-2026/）；Medium（https://medium.com/ai-software-engineer/anthropic-just-made-claude-sonnet-5-offer-pricing-permanent-c51d293bb3e8）

2. **主推工具動態／成本情報｜OpenAI Codex恢復「5小時用量上限」機制，並推出更省用量的GPT-5-Codex-Mini**
   新聞內容：OpenAI工程負責人Tibo Sottiaux於X宣布，自8月25日起Codex CLI／ChatGPT Work的Plus方案將重新啟用先前暫時取消的「5小時用量上限」，官方說法是為了平滑運算資源負載、避免臨時性用戶不小心一次用完整週額度；Pro（100/200美元）方案在近幾個月仍維持不受此限制影響。同時，Codex CLI與IDE擴充新增了更省成本的GPT-5-Codex-Mini選項，當用量達到5小時額度的90%時會自動提示切換，號稱在相同訂閱額度下可多出約4倍可用量。這是Codex在一個月內第二次調整用量政策（此前才在7月底短暫取消限制），顯示OpenAI仍在頻繁調整免費／付費額度規則。
   為什麼對我們有意義：若工程部或企劃室有人使用Codex CLI（而非Claude Code）作為輔助開發工具，這次限制恢復可能讓重度使用者在工作尖峰時段被迫中斷或降級到Mini模型，影響交付節奏；由於公司目前以Claude系列為主推工具，Codex用量政策的不穩定性也可作為佐證「以Claude Code為主、Codex為輔」策略的合理性，工程主管可據此提醒團隊審慎評估是否讓關鍵流程依賴Codex的Plus方案。
   建議後續：工程主管盤點目前團隊中仍在用ChatGPT Plus／Codex CLI（非企業方案）的成員，評估是否需要升級方案或改以Claude Code取代，避免尖峰時段被迫降級到Mini模型影響產出品質。
   來源：Tibo Sottiaux on X（https://x.com/thsottiaux/status/2076365965915467978）；9to5Mac（https://9to5mac.com/2026/08/24/openai-restores-5-hour-codex-and-work-limits-for-chatgpt-plus-users/）；OpenAI Help Center（https://help.openai.com/en/articles/9624314-model-release-notes）

3. **平台治理／資安｜舊版Claude模型（Opus 4.6／Opus 3／Haiku 4.5）被曝可用多輪話術繞過內容政策，產出違規性內容**
   新聞內容：TechCrunch於8月21日報導，一名英國研究者以「多輪角色扮演」技巧測試Claude Opus 4.6，透過先建立無害的虛構情境、再反覆質疑模型「拒絕回應是對某一性別不公平（帶有厭女意味）」的方式，逐步誘導模型在10次直接請求中10次都產出違反Anthropic使用政策、明確禁止的色情內容；8月24日追蹤報導確認同樣手法對Opus 3、Haiku 4.5等舊模型同樣有效，但Opus 4.7以後至目前的Opus 5系列已能抵禦此手法。Anthropic目前並未下架Opus 4.6、Opus 3、Haiku 4.5，這些舊版模型仍可透過API正常呼叫。
   為什麼對我們有意義：若公司內部有任何對外服務（例如玩家客服機器人、社群聊天輔助、遊戲內NPC對話生成）仍呼叫Opus 4.6或更舊的Claude模型作為底層引擎，就存在被玩家或惡意使用者利用類似多輪話術「調戲」出違規內容的風險，一旦發生會直接影響公司品牌形象與遊戲分級合規（尤其涉及未成年玩家保護時風險更高）；這屬於資安／內容治理層面的實際攻擊面，而非單純學術研究。
   建議後續：資安／技術窗口立即清查目前所有對外或半對外服務（客服、社群、遊戲內容生成）呼叫的Claude模型版本，若仍使用Opus 4.6、Opus 3或Haiku 4.5，優先評估升級至Opus 4.7以上或改用具備最新防護的模型版本；企劃室與客服團隊評估是否需額外加裝內容過濾層（如關鍵字或分類器）作雙重防護。
   來源：TechCrunch（https://techcrunch.com/2026/08/21/anthropics-opus-4-6-is-a-smut-machine/）；The AI Insider（https://theaiinsider.tech/2026/08/24/older-claude-models-found-vulnerable-to-jailbreak-producing-explicit-content-testing-shows/）

4. **主推工具動態｜Claude Code連續發布v2.1.243～v2.1.245，新增企業自訂費率與/loop用量追蹤，並修復Linux啟動當機**
   新聞內容：Claude Code在v2.1.243新增了`/usage`指令下的「Loops細分」功能，可顯示每個`/loop`排程任務的執行次數、總token用量、平均單次token數與最後執行時間，方便抓出異常吃資源的排程任務；同版本也新增`modelPricing`這項受管理設定，讓企業可依自己與Anthropic談定的合約費率覆蓋預設牌價，使`/cost`與狀態列顯示的成本數字更貼近真實帳單，另外新增`promptCacheTtl`／`subagentPromptCacheTtl`設定，讓API金鑰與雲端用戶可將主對話的prompt cache延長維持在1小時。緊接著v2.1.245（8月25日發布）修復了在glibc 2.44（如Arch Linux、CachyOS、Fedora Rawhide）環境下Claude Code啟動即當機的問題。
   為什麼對我們有意義：`modelPricing`功能對IT／財務部門特別重要——如果公司未來與Anthropic簽署企業合約費率，就能讓每位工程師、企劃在終端機看到的成本數字直接反映公司實際議定價格，而非公開牌價，有助於部門間成本歸因與預算控管；`/loop`用量細分則能幫工程主管快速找出哪些自動化排程任務（例如CI檢查、每日報表）意外燒掉過多token額度。
   建議後續：IT／工程主管更新內部Claude Code版本至v2.1.245以上，若公司已有或計畫簽署企業合約費率，請窗口研究如何設定`modelPricing`；同時盤點內部是否有跑在Linux（尤其Arch/Fedora系）環境的CI或開發機，確認更新後啟動當機問題已解決。
   來源：Claude Code Changelog（https://code.claude.com/docs/en/changelog）；Havoptic（https://www.havoptic.com/tools/claude-code）；Gradually.ai（https://www.gradually.ai/en/changelogs/claude-code/）

7. **產業應用（程式）｜Epic Games將Unreal MCP正式開放給UEFN（Fortnite創作者平台），agent可直接操作Verse程式碼與場景編輯**
   新聞內容：Epic Games於8月20日宣布，原本隨UE 5.8推出的Unreal MCP（Model Context Protocol）橋接功能，正式支援進駐UEFN（Unreal Editor for Fortnite）。開發者只需在專案設定的Beta Access選項中開啟「UEFN MCP Toolset」，不需另外安裝外部外掛，即可讓Claude Code、Cursor等具備MCP能力的agent工具，直接連接編輯器撰寫並編譯Verse程式語言、放置與設定裝置（Devices）、建立Scene Graph場景物件、用UMG搭建介面，甚至直接執行遊玩測試。社群也已出現如`uefn-verse-mcp`等第三方橋接工具，讓agent能更安全地驅動UEFN即時編輯器。
   為什麼對我們有意義：對程式團隊而言，這代表主要遊戲引擎（Unreal／UEFN）與公司主推的Claude Code等agent工具的整合正式進入官方支援層級，若公司有在Fortnite創作者平台或Unreal生態系開發專案的計畫，工程師未來可直接用agent自動化Verse腳本撰寫、場景搭建與測試流程，減少重複性的編輯器操作；即使目前公司主力引擎非UEFN，這也預示Unity、Unreal本體未來會加速把類似MCP整合帶入主線編輯器，值得工程部提前關注。
   建議後續：若公司有Unreal / UEFN相關專案，工程主管可安排1名工程師實測UEFN MCP Toolset搭配Claude Code的工作流程，評估在場景搭建與Verse腳本撰寫上的實際提效幅度；若無UEFN專案，可持續觀察Unreal Engine本體是否推出對應功能。
   來源：Fortnite官方公告（https://www.fortnite.com/news/unreal-mcp-is-now-available-in-uefn）；Inven Global（https://www.invenglobal.com/articles/24955/speeding-up-development-with-ai-uefn-supports-unreal-mcp-plugin-starting-aug-20）；GitHub - quangdang46/uefn-verse-mcp（https://github.com/quangdang46/uefn-verse-mcp）
