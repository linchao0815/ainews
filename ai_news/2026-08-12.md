1. **主推工具動態｜資安｜Claude Code v2.1.228修復「同步技能」資安漏洞，曾可悄悄覆蓋本機指令並執行shell程式碼**
   新聞內容：Anthropic於8月11日發布Claude Code v2.1.228，本次更新包含18項CLI變更，其中最關鍵的是一項資安修補：先前從claude.ai同步下來的skills（技能），若與使用者本機的slash指令或MCP prompt同名，會直接「蓋掉」本機指令優先執行，且這類同步技能的內容可包含`!`shell指令與`@`檔案展開語法，等同能在使用者不知情的狀況下執行任意shell程式碼。修復後，本機指令一律優先於同步技能，技能描述會被清洗（sanitize）並加註標籤讓使用者辨識來源，且同步技能在本機不再能觸發shell執行或檔案展開。Anthropic官方帳號@ClaudeCodeLog已在X上公布本次18項變更的完整清單。
   為什麼對我們有意義：我們工程與企劃團隊日常使用Claude Code，若曾啟用claude.ai的技能同步功能（例如跨裝置共用常用skill），舊版本存在「技能冒充本機指令、悄悄執行shell指令」的風險，等同外部同步內容有機會在本機取得執行能力，屬於實質資安漏洞，而非理論風險。
   建議後續：工程主管應立即通知全體Claude Code使用者更新至v2.1.228以上版本，並請資安人員確認近期是否有人回報過「輸入指令卻觸發非預期行為」的異常紀錄，若有應進一步排查是否與此漏洞相關。
   來源：GitHub（https://github.com/anthropics/claude-code/releases/tag/v2.1.228）；Claude Code Changelog on X（https://x.com/ClaudeCodeLog/status/2087274049709707404）；Clauding（https://clauding.de/en/posts/claude-code-2-1-228）

2. **主推工具動態｜Google Antigravity CLI發布2.7.1版，新增圖片並排比對與無障礙功能強化**
   新聞內容：Google於8月11日發布Antigravity CLI 2.7.1版，新增圖片檔案（含SVG）在`/diff`比對模式下的並排視覺預覽功能，並大幅強化螢幕閱讀器與鍵盤操作的無障礙支援；同時修復diff檢視器在多行換行或留言展開時會出現畫面抖動、狀態列被推出畫面外的問題。此為繼8月初新增`--project`旗標與內建`antigravity_guide`技能後，Antigravity CLI在同一個月內的第二波更新，顯示Google正密集迭代這款Gemini CLI後繼工具。
   為什麼對我們有意義：對「程式」與「美術」團隊而言，若正在評估或已使用Antigravity CLI做程式碼審查，新增的圖片並排比對功能對於需要同時審視UI截圖、貼圖、美術素材變更的PR（例如美術資源更新、UI調整）特別實用，能省去額外開圖片比對工具的步驟；無障礙功能強化也有助於團隊中使用輔助工具的同仁。
   建議後續：建議工程主管指派一名工程師更新至2.7.1版，並在下一次涉及美術資源或UI變更的PR審查中實測圖片並排diff功能，評估是否能納入團隊標準程式碼審查流程。
   來源：Google Antigravity Changelog（https://antigravity.google/changelog）；GitHub（https://github.com/google-antigravity/antigravity-cli/blob/main/CHANGELOG.md）

3. **產業動態｜成本情報｜Meta搶進coding agent市場推出Muse Code，「貢獻者方案」用你的程式碼換低價引發資安疑慮；同步發布可跑在消費級顯卡的開源模型Muse Glimmer**
   新聞內容：Meta Superintelligence Labs於8月5日由AI主管Alexandr Wang在X上親自宣布推出「Muse Code」公測版——這是Meta首款終端機coding agent，由專屬模型Muse Spark 1.2驅動，具備多個子agent在獨立worktree中平行協作、跨session保留專案上下文等能力，直接對標Claude Code、Cursor與Codex。官方公布的定價設計為兩檔：標準費率，以及費用明顯較低的「貢獻者（contributor）方案」，但代價是Meta會將使用者的prompt與程式碼輸出用於訓練自家模型。緊接著8月10日，Wang在X上宣布即將開源Muse Spark 1.2的權重版本，並直接發布採用Apache 2.0授權的300億參數模型「Muse Glimmer」，官方宣稱其可在僅24GB VRAM的消費級顯卡上運行，且不犧牲agentic任務的可靠性。
   為什麼對我們有意義：對「程式」與資安團隊而言，Muse Code代表coding agent市場再添一個資源雄厚的競爭者，未來若有工程師自行嘗試，公司必須明確禁止使用「貢獻者方案」處理任何公司程式碼或未上架專案內容，否則等同主動把內部程式碼、企劃邏輯交給Meta訓練其模型，是嚴重的資料外洩風險；另一方面，開源的Muse Glimmer可在單張消費級顯卡本機運行，對於希望降低API成本、或想在無網路/高機密環境執行低敏感度自動化任務（如批次格式轉換、內部工具腳本）的團隊，是值得評估的免費替代方案。
   建議後續：IT／資安主管應立即將「禁止使用Muse Code貢獻者方案處理公司程式碼」納入AI工具使用規範並公告全體工程師；同時可指派一名工程師在獨立測試機上試跑開源Muse Glimmer，評估其在本機自動化任務上的表現是否足以取代部分低敏感度、高頻呼叫的付費API用量。
   來源：TechCrunch（https://techcrunch.com/2026/08/05/meta-launches-muse-code-an-ai-agent-for-large-code-bases/）；CNBC（https://www.cnbc.com/2026/08/05/meta-debuts-muse-code-to-take-on-anthropic-and-openai-.html）；Alexandr Wang on X（https://x.com/alexandr_wang/status/2085081073571246106；https://x.com/alexandr_wang/status/2086756152034066792）

4. **GitHub趨勢｜開源「OfficeCLI」讓AI agent直接讀寫Word／Excel／PowerPoint，短短數週從1.3萬星衝上2.7萬星**
   新聞內容：開源專案iOfficeAI/OfficeCLI是一套專為AI agent設計的Office文件操作工具，以單一執行檔（不需安裝微軟Office）就能讓Claude Code、Cursor、GitHub Copilot等AI coding agent直接讀取、編輯、自動化處理Word、Excel與PowerPoint檔案，並內建HTML／PNG高還原度渲染引擎可將文件轉為圖片預覽。該專案在2026年7月才剛突破1.3萬顆星，短短數週內已衝上2.7萬顆星、近1,900次fork，成長速度在GitHub上備受關注，且工具會自動偵測使用者裝有哪些AI coding工具並自動安裝對應的skill設定檔。
   為什麼對我們有意義：對「企劃室」與「運營」團隊而言，我們大量日常產出（企劃書、活動提案、營運週報、數據報表、對外簡報）都是Word／Excel／PowerPoint格式，這套工具讓Claude Code或Cursor這類我們已經在用的AI coding agent，能直接自動生成或更新這些Office文件，而不需要人工在Office軟體裡逐項貼上內容，有機會大幅縮短企劃文件初稿撰寫與週報彙整的時間。
   建議後續：建議企劃室指派1名同仁試裝OfficeCLI，挑選一項重複性高的文件工作（如每週營運數據Excel報表自動彙整、企劃提案PPT初稿產出）進行概念驗證，評估產出品質與省下的工時，再決定是否推廣為企劃室常用工具。
   來源：GitHub（https://github.com/iOfficeAI/OfficeCLI）；betterhn50 on X（https://x.com/betterhn50/status/2074251044930904166）；CoddyKit（https://www.coddykit.com/pages/blog-detail?id=512903&slug=officecli-the-open-source-office-suite-that-gives-ai-agents-full-control-over-wo）

5. **工具能力｜TrustScale推出「Argus」AI幻覺偵測與修正平台，號稱98.5%準確率、可套用在任何LLM輸出上**
   新聞內容：AI訓練與評測公司TrustScale於8月4日發布「Argus」，這是一套即時偵測與修正AI幻覺內容的平台，會以色標（TrustScore）標示AI輸出內容中的可疑陳述，並提供具實證依據的修正建議，而非單純用「另一個AI去檢查AI」的方式，而是採用實證證據與確定性驗證比對。官方宣稱其抓錯準確率達98.5%，速度比人工查證快135倍，可套用在ChatGPT、Claude、Gemini、Copilot、Grok等任何模型的輸出上，企業版已可在私有或公開資料環境安裝，目前支援12種語言，個人版則以研究預覽形式開放。
   為什麼對我們有意義：對「企劃」與「運營／客服」團隊而言，若我們已經或計畫用AI協助生成玩家客服回覆範本、社群公告、行銷文案或活動說明等對外內容，這類幻覺偵測工具能在人工審核前先自動抓出AI編造的錯誤數字、不存在的活動規則或錯誤事實，降低錯誤內容真的曝光給玩家、引發客訴或輿論風波的風險，屬於可直接補進現有內容產出流程的品管關卡。
   建議後續：建議企劃室與客服主管挑選一項目前用AI輔助產出對外文案的流程（如活動公告草稿），評估導入Argus或同類事實查核工具作為人工審核前的自動化第一關，並比較其抓錯效果與導入成本。
   來源：Morningstar／ACCESSWIRE（https://www.morningstar.com/news/accesswire/1198968msn/trustscale-launches-argus-to-detect-and-correct-ai-hallucinations-and-power-safe-enterprise-ai-adoption）；IT Business Net（https://itbusinessnet.com/2026/08/trustscale-launches-argus-to-detect-and-correct-ai-hallucinations-and-power-safe-enterprise-ai-adoption/）

6. **產業動態｜微軟自建模型Project Polaris本月起取代GitHub Copilot預設的GPT-4 Turbo，全體訂閱戶自動遷移**
   新聞內容：微軟於6月Build大會宣布的自建coding模型「Project Polaris」（採混合專家架構、針對程式語言分模組調校），已排定自2026年8月起正式取代GPT-4 Turbo，成為GitHub Copilot所有訂閱方案的預設推理引擎，所有既有用戶會被自動遷移，不需變更方案或額外付費，並提供最長3個月的GPT-4回退選項供需要緩衝的團隊使用；微軟宣稱Polaris在HumanEval、MBPP等基準測試上優於GPT-4 Turbo，尤其在Rust、Haskell等低資源語言上進步明顯，但該數字尚未經第三方獨立驗證。
   為什麼對我們有意義：若我們「程式」團隊中有人將GitHub Copilot作為Claude Code／Cursor之外的輔助工具，本月起其程式碼建議的風格與品質會在未經同事主動選擇的情況下自動改變，屬於會影響既有工作流程的變更；更廣義來看，這也是大型平台商為降低對單一模型供應商（OpenAI）依賴、掌控成本而自建模型的又一案例，值得我們在評估Claude／Cursor／Antigravity等主推工具的長期供應商風險與備援方案時，納入參考。
   建議後續：建議工程主管確認團隊內是否仍有人使用GitHub Copilot處理日常工作，若有，提醒其留意8月起輸出品質可能出現落差，並可安排一週內在既有專案上比對新舊模型的程式碼建議差異，作為是否需要用回退選項或改用公司主推工具的參考。
   來源：TechCrunch（https://techcrunch.com/?p=2516780）；Enterprise DNA（https://enterprisedna.co/resources/news/microsoft-build-2026-project-polaris-copilot-recap-2026/）；Let's Data Science（https://letsdatascience.com/blog/microsoft-project-polaris-replaces-gpt4-github-copilot）
