## 1. **主推工具動態｜Claude Code v2.1.285上線：新增`allowedProviders`鎖定API供應商、`CLAUDE_CODE_DISABLE_WEB_FETCH`可全面關閉自動抓網頁**
   **新聞內容**：Anthropic於9/29發布Claude Code v2.1.285，是繼9/26的v2.1.283、9/28的v2.1.284（搭配Sonnet 5.5上線）之後本月第三波重大更新。本次共136項變更（86項修復、23項調整、17項改善、10項新增），重點包括：新增`allowedProviders`設定值，可限制單一機器只能呼叫指定的API供應商；新增環境變數`CLAUDE_CODE_DISABLE_WEB_FETCH`，可完全關閉WebFetch工具與工具執行過程中的自動網頁抓取；背景執行的Bash／PowerShell指令現在預設30分鐘、最長2小時就會被強制中止；另新增`claude --desktop`指令可直接在目前目錄或指定session開啟桌面版App。
   **為什麼對我們有意義**：`allowedProviders`與`CLAUDE_CODE_DISABLE_WEB_FETCH`是直接對應資安／資料外洩風險的治理功能——如果公司要求Claude Code只能連到核准的模型供應商（例如僅限Anthropic官方或特定雲端代理），或擔心agent在執行任務時意外把內部程式碼／機密內容透過WebFetch送到未知網站，現在可以用設定檔直接鎖死，不必再靠人工規範。背景指令逾時強制中止則能避免工程師誤跑長迴圈腳本吃滿授權額度或拖垮CI機台。
   **建議後續**：資訊安全窗口與工程主管應立即在公司統一的Claude Code設定檔（settings.json）中評估導入`allowedProviders`與`CLAUDE_CODE_DISABLE_WEB_FETCH`，作為內部資安基準線的一部分，而非留給個別工程師自行決定。
   **來源：**GitHub Release Notes（[https://github.com/anthropics/claude-code/releases/tag/v2.1.285](https://github.com/anthropics/claude-code/releases/tag/v2.1.285)）；dev.classmethod.jp（[https://dev.classmethod.jp/en/articles/20260930-cc-updates-v2-1-285/](https://dev.classmethod.jp/en/articles/20260930-cc-updates-v2-1-285/)）；X／Claude Code Changelog（[https://x.com/ClaudeCodeLog/status/2104989569296859563](https://x.com/ClaudeCodeLog/status/2104989569296859563)）

## 4. **平台治理／資安｜EY最新調查：98%大型企業已有AI治理政策，卻有47%坦承曾為求快速上線而繞過，36%曾因AI事故造成實質損害**
   **新聞內容**：資誠（EY）於9/15發布的最新調查顯示，受訪大型企業中高達98%表示已建立AI治理政策，但其中47%坦承曾為了趕上緊急部署時程而繞過既有治理流程；89%的受訪者表示過去一年曾遇過AI相關風險，36%表示曾發生造成資料遺失、財務損失、營運中斷或品牌損害等「實質損害」的AI事故；另有58%高階主管表示公司過去一年曾發生AI相關資安事件或有驚無險的狀況。這份調查與9/28已報導的AWS「影子AI」報告是不同機構、不同角度的獨立研究，但結論高度一致：企業導入AI agent的速度已明顯超前治理與資安控管的建置速度。
   **為什麼對我們有意義**：這則調查點出一個具體風險模式——「政策有寫，但趕專案時會被繞過」，這與遊戲產業常見的「版本上線前衝刺」文化高度相似，若公司內部也有AI使用規範，最容易在上線前趕工期間被暫時擱置，形成資安破口。運營與企劃團隊若有使用AI工具處理玩家個資、金流資料或未發布內容，尤其要注意這類「趕工例外」情境。
   **建議後續**：資安／法務窗口可規劃一次內部稽核，抽查近期上線專案期間是否有AI使用規範被暫時放寬的紀錄，並研議是否需要為「趕工期間」訂定明確的例外審核機制，而非讓規範直接被跳過。
   **來源：**EY官方（[https://www.ey.com/en_us/newsroom/2026/09/ey-survey-finds-that-autonomous-ai-implementation-outpaces-oversight-yielding-an-ai-governance-gap](https://www.ey.com/en_us/newsroom/2026/09/ey-survey-finds-that-autonomous-ai-implementation-outpaces-oversight-yielding-an-ai-governance-gap)）；CDO Magazine（[https://cdomagazine.tech/aiml/ai-governance-isnt-keeping-pace-with-agentic-ai-ey-survey-finds](https://cdomagazine.tech/aiml/ai-governance-isnt-keeping-pace-with-agentic-ai-ey-survey-finds)）

   **新聞內容**：騰訊開源專案WeKnora在9/21至9/27這週的GitHub趨勢榜上排名第五，star數達3萬0,736顆（首次登上榜首則是2025年11月）。WeKnora是一個LLM知識平台，能把原始文件（如PDF、Word、會議紀錄）自動轉換成可查詢的RAG知識庫，並額外附加一個能做多步驟推理的agent，以及一個會隨著文件更新而自動改寫、自我維護的Wiki，三者共用同一份底層知識庫。近期版本並新增與DeepSeek Harness外掛整合的唯讀檢索工具。
   **為什麼對我們有意義**：企劃室與運營／客服團隊經常面臨「規則文件、活動企劃書、玩家常見問題散落各處、版本更新後舊文件沒人維護」的困境。WeKnora這類工具的價值在於它不只是被動的RAG問答，而是能自動把新文件內容整合進一份會持續更新的Wiki，對於維護內部SOP庫、玩家客服知識庫（FAQ隨版本更新自動改寫）有直接對應的應用場景，且為開源專案、無需額外授權費用。
   **建議後續**：企劃室可指派1名人員以近期的活動規則文件與客服QA為測試素材，小範圍架設WeKnora試跑一週，評估其自動整理與檢索品質是否足以取代目前手動維護的內部wiki。
