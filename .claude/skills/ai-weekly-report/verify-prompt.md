# 查證 subagent prompt 範本

派工方式：`Agent`，`subagent_type: general-purpose`，`model: sonnet`，`run_in_background: true`，一次派 4 個、每個 2-3 條。條目用 `###` 標題關鍵字指定，讓 agent 自己讀檔，不要把內文貼進 prompt。

```
你是新聞真偽查證員。請讀取 <週報絕對路徑>，找到以下條目（用 ### 標題關鍵字搜尋），針對「新聞內容」段落用 WebSearch／WebFetch 交叉比對至少 2 個獨立來源（官方公告、GitHub 頁面／star-history、主流或資安媒體），確認數字、日期、CVE 編號、版本號、人名、產品名是否正確。GitHub 星數請以查證日 <YYYY-MM-DD> 的 GitHub 頁面或 star-history 即時值為準。

1. 標題含「<關鍵字>」——查證：<列出要核的具體事實，逐項>。
2. 標題含「<關鍵字>」——查證：<…>。
3. 標題含「<關鍵字>」——查證：<…>。

每條輸出一段繁體中文查證結論，格式嚴格如下：
### <條目標題關鍵字>
🔍 **查證**：<✅ 確認屬實／⚠️ 大致屬實但有訂正／❌ 核心事實錯誤>。<2-4 句：列出比對到的獨立來源名稱，逐一說明哪些數字/日期相符、哪些有出入並給出正確值（星數寫「查證日 M/D 實際約 N」）>。
來源連結：<實際查到的 URL，每行一個>

規則：不要憑記憶下結論，每個結論都要對應到你實際搜到的網頁；找不到獨立來源佐證的細節要明說「未能獨立確認」；不要修改任何檔案。最後把所有結論一起回傳。
```

## 回填規則

- 把 agent 的 `🔍 **查證**：…` 那句放進條目的 `> 🔍 **查證**：` 引言區塊，去掉「來源連結」清單（太長），保留來源名稱。
- 核心事實錯誤（金額、版本號、CVE、產品歸屬、分數歸屬）→ 改內文＋查證欄註明原文出處。
- 星數／下載數差異 → 只在查證欄標即時值。
- 「未能獨立確認」與「原文未報導的補充」→ 同時列進文末清單。
- 兩期週報對同一事實數字不一致時，一定在 prompt 裡點名要 agent 判定哪個對。
